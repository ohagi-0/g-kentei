# 09 AIに関する法律と契約

> 重点分野（法律・倫理）。技術の章と違い、仕組みの理解よりも **「どの法律が何を守るか」「AIのどの場面で問題になるか」** の対応づけが問われる。条文番号を覚えるより、**定義の境目**（個人情報かどうか、著作物かどうか、営業秘密かどうか）と **契約の型**（請負か準委任か）を事例に当てはめられることが目標。法律・ガイドラインは 2026-10-23 時点の情報で書いている。倫理・ガバナンス・海外の規制（EU AI法、AI推進法など）は10章で扱う。

## この章で押さえること

- AIのライフサイクル（**データを集める → 学習する → 生成・利用する → 契約で取引する**）の各場面に、どの法律が効くかを対応させる。**個人情報保護法＝人の情報**、**著作権法＝表現**、**特許法＝技術的アイデア**、**不正競争防止法＝秘密・限定提供のデータ**、**独占禁止法＝市場の競争**。
- 著作権は **「学習段階（30条の4で原則として許諾不要）」と「生成・利用段階（通常の著作権侵害の判断）」を分けて考える**。AI生成物に著作権が生じるかは **人間の創作的寄与** があるかで決まる。
- 個人情報は **個人情報 ⊃ 個人データ ⊃ 保有個人データ** の包含関係と、**匿名加工情報（元に戻せない）／仮名加工情報（照合すれば戻せる）** の違いが頻出。2026年7月に、AI開発を含む統計作成目的なら同意なしで第三者提供できる特例などを盛り込んだ改正法が成立した（施行は公布から2年以内）。
- AI開発契約は経産省「AI・データの利用に関する契約ガイドライン」の **探索的段階型（アセスメント → PoC → 開発 → 追加学習）** と、**準委任（完成義務なし）／請負（完成義務あり）** の使い分けがポイント。学習済みモデルの権利は「どちらのものか」より **「利用条件」で調整する** のが基本の考え方。

## 全体像: AIのライフサイクルと法律の対応

```
[データを集める] ── 個人情報保護法（個人情報を含むか、利用目的、第三者提供、越境移転）
     │             ├ 著作権法（Web上の文章・画像を集める → 30条の4）
     │             ├ 不正競争防止法（他社の営業秘密・限定提供データを不正に取っていないか）
     │             └ 利用規約・契約（サイトの規約、データ提供契約）
     ▼
[学習する]    ── 著作権法30条の4（情報解析は原則として許諾不要。ただし例外あり）
     │             └ 個人情報保護法（学習目的が利用目的の範囲内か）
     ▼
[生成・利用する] ─ 著作権法（生成物が既存作品に「類似」＋「依拠」なら侵害）
     │             ├ AI生成物の著作物性（人間の創作的寄与があるか）
     │             └ 個人情報保護法（プロンプトに個人データを入れてよいか）
     ▼
[成果を守る・取引する]
                   ├ 特許法（AIを使った発明。発明者は人間のみ）
                   ├ 不正競争防止法（ノウハウ・データを秘密や限定提供で守る）
                   ├ 契約（開発委託: 請負/準委任、SaaS: 利用規約・データ利用権・精度保証）
                   └ 独占禁止法（データやAI基盤を持つ企業による競争の制限）
```

### 法律の対応表（何を守る法律か／AIとの関係／試験のひっかけ）

| 法律 | 何を守る法律か | AIとの関係（典型場面） | 試験のひっかけ |
|---|---|---|---|
| **個人情報保護法** | **生存する個人**の権利利益（個人情報の適正な取扱い） | 学習データ・プロンプトに個人情報が含まれる。顔画像・購買履歴の分析。データの第三者提供・海外のクラウドへの移転 | 死者の情報は原則対象外／**委託は第三者提供ではない**（同意不要）／匿名加工情報は元に戻せないが、仮名加工情報は照合すれば戻せる／取扱件数による適用除外はない（2017年に撤廃） |
| **著作権法** | **思想・感情の創作的な表現**（アイデアは守らない） | Web上の文章・画像を学習に使う（**30条の4**）。生成物が既存作品に似る。AI生成物に権利が生じるか | 権利は**創作した時点で自動的に発生**（登録不要）／**学習段階と生成・利用段階を分けて考える**／画風・作風（アイデア）は原則保護されない／「AIが作ったもの」でも人間の創作的寄与があれば著作物になりうる |
| **特許法** | **自然法則を利用した技術的思想の創作**（発明） | AIを使った発明、学習方法・モデル構造の発明 | 出願・審査・登録が必要（自動では生じない）／存続期間は**出願から20年**／**発明者は自然人に限る**（AIは発明者になれない） |
| **不正競争防止法** | 事業者間の公正な競争（**営業秘密**・**限定提供データ**を不正取得から守る） | 学習データ・ノウハウ・ハイパーパラメータなどを秘密として守る。有償で特定の相手に提供するデータを守る | 営業秘密は**3要件**（秘密管理性・有用性・非公知性）／限定提供データは**秘密でなくてよい**（限定提供性・相当蓄積性・電磁的管理性）／登録は不要 |
| **独占禁止法** | 公正かつ自由な**市場の競争** | データやAI基盤（計算資源・基盤モデル）の囲い込み、自社優遇、価格決定アルゴリズムによる協調 | 「データを大量に持つこと」自体は違法ではない。問題は**競争を制限・阻害する行為** |
| **民法（契約）** | 当事者間の合意（契約自由） | AI開発の委託（請負・準委任）、SaaS型AIサービスの利用規約 | **準委任は完成義務を負わない**／AI開発は結果が予測しにくいので、PoCなどは**準委任が向く**／データそのものには所有権がない（所有権は「物」が対象）ので、**契約で利用条件を決める** |

## 9-1 個人情報保護法

**個人情報保護法**（個人情報の保護に関する法律）は、個人情報の有用性に配慮しながら、**個人の権利利益を守る**ための法律。2003年成立、2005年全面施行。おおむね3年ごとに見直され、AIに関係の深い改正が続いている。所管は**個人情報保護委員会**（PPC）。

| 改正 | 施行 | AIに関係する主な内容 |
|---|---|---|
| 2015年改正 | 2017年5月 | **個人識別符号**・**要配慮個人情報**・**匿名加工情報**を新設。取扱件数5,000件以下の事業者を対象外とする規定を撤廃（小さな事業者も対象に）。個人情報保護委員会を設置 |
| 2020年（令和2年）改正 | 2022年4月 | **仮名加工情報**・**個人関連情報**を新設。**漏えい等の報告・本人通知を義務化**。保有個人データから「6か月以内に消去するもの」を除く規定を廃止。越境移転時の情報提供を強化 |
| 2021年（令和3年）改正 | 2022年4月〜2023年4月 | 民間・行政機関・独立行政法人・地方公共団体のルールを1本の法律に統合（官民一元化） |
| **2026年（令和8年）改正** | **公布（2026年7月17日）から2年以内** | **統計作成等（AI開発を含む）のための同意不要の特例**、顔特徴データ等の規律、16歳未満のこどもの規律、**課徴金制度**の導入、罰則の強化（詳しくは後述） |

### 用語の定義（包含関係が最頻出）

```
個人情報（生存する個人に関する情報で、特定の個人を識別できるもの）
 └ 個人データ（個人情報データベース等＝検索できるように体系化されたもの を構成する個人情報）
     └ 保有個人データ（事業者が開示・訂正・利用停止などの権限を持つ個人データ）
```

| 用語 | 一言で | 例 | ポイント |
|---|---|---|---|
| **個人情報** | **生存する**個人に関する情報で、特定の個人を識別できるもの | 氏名、顔写真、氏名と結びついた購買履歴 | **ほかの情報と容易に照合**して識別できるものも含む。死者の情報は原則として対象外（遺族の個人情報になる場合はある）。法人の情報も対象外 |
| **個人識別符号** | **それだけで**特定の個人を識別できる符号 | ①身体の特徴を変換したもの（**顔認識データ**、指紋、DNA、虹彩、声紋）②個人に割り当てた番号（**マイナンバー**、旅券番号、運転免許証番号、基礎年金番号） | これを含めば氏名がなくても個人情報。**電話番号・メールアドレス・クレジットカード番号は個人識別符号ではない**（ほかの情報と組み合わさって個人情報になることはある） |
| **個人データ** | データベース化された個人情報 | 顧客管理システムの顧客情報、名刺管理ソフトの情報 | 安全管理措置・第三者提供の制限などの義務は**個人データ**にかかる |
| **保有個人データ** | 本人が**開示・訂正・利用停止等を請求できる**個人データ | 通販サイトの会員情報 | 委託を受けて預かっているだけのデータは含まない。**2022年4月から、短期間（6か月以内）で消去するデータも含まれる** |
| **要配慮個人情報** | 不当な差別や偏見が生じないよう**特に配慮が必要**な個人情報 | 人種、信条、社会的身分、病歴、犯罪の経歴、犯罪被害の事実、障害、健康診断の結果、診療・調剤の情報、刑事事件・少年事件の手続 | **取得に原則として本人の同意が必要**。**オプトアウトによる第三者提供は禁止**。**労働組合への加盟や性的指向は、日本法の要配慮個人情報の列挙には入っていない**（GDPRの特別カテゴリーには入る） |
| **個人関連情報** | 生存する個人に関する情報で、個人情報・仮名加工情報・匿名加工情報のどれにも当たらないもの | Cookie、閲覧履歴、位置情報（それだけでは個人を識別できないもの） | 提供先で個人データになると想定されるときは、**本人が同意しているかを提供元が確認**する義務（2022年〜） |

#### 問われ方
- 「個人情報に当たるものはどれか」→ 個人識別符号（顔認識データ、マイナンバー）を含む情報、ほかの情報と容易に照合できる情報。**亡くなった人の情報**、**法人の情報**、**統計情報**は原則として当たらない。
- 「個人情報 ⊃ 個人データ ⊃ 保有個人データ」の順序。
- 要配慮個人情報の例を選ぶ問題。「病歴」「犯罪の経歴」は該当、「本籍地」「労働組合への加盟」「性的指向」は日本法の列挙には入っていない（労働組合への加盟は、金融分野などで別に「機微情報」として扱われる）。

### 匿名加工情報と仮名加工情報

どちらも「個人情報を加工して、使いやすくする」ための仕組み。**元に戻せるかどうか**と**誰が使えるか**が違う。

| | 匿名加工情報 | 仮名加工情報 |
|---|---|---|
| 新設 | 2015年改正（2017年施行） | 2020年改正（2022年施行） |
| 加工の程度 | 特定の個人を識別できず、**元の個人情報に復元できない**ように加工 | **ほかの情報と照合しない限り**特定の個人を識別できないように加工（**照合すれば戻せる**） |
| 主な用途 | **社外**に提供・流通させる（データ販売、共同研究） | **社内**での分析（AIの学習、統計分析） |
| 第三者提供 | **本人の同意なしで可能**（作成時と提供時に項目を**公表**し、提供先に匿名加工情報であることを**明示**する） | **原則禁止**（委託・共同利用などは可） |
| 利用目的の変更 | ― | 当初の利用目的を超えて変更できる（変更後の目的を公表） |
| 主な義務 | 再識別（元の本人を特定しようとすること）の禁止 | 元データとの照合の禁止、本人への連絡の禁止。**漏えい報告・開示請求等の対象外** |
| 個人情報か | 個人情報ではない | 多くの場合、作った事業者の中では個人情報のまま（照合できる元データを持っているため） |

- **なぜ仮名加工情報が作られたか**: 匿名加工情報は「復元できない」レベルまで加工する必要があり、分析に必要な情報まで削られて使いにくかった。社内でAIの学習や分析に使うだけなら、そこまで加工しなくてもよい、という需要に応えた。
- **問われ方**: 「照合すれば個人を識別できる」→ 仮名加工情報。「本人の同意なしに第三者へ提供できる」→ 匿名加工情報。「仮名加工情報は第三者に提供できる」は**誤り**。

### 利用目的・取得・第三者提供・委託

| 場面 | ルール |
|---|---|
| **利用目的** | 取得時に**できる限り特定**し、本人に通知または公表する。特定した目的の範囲を超えて使うには、原則として**本人の同意**が必要（目的外利用の禁止） |
| 取得 | 偽りなどの不正な手段で取得しない（適正取得）。**要配慮個人情報の取得は原則として本人の同意が必要** |
| 安全管理 | 漏えい等を防ぐ措置。従業者・委託先の監督。一定の漏えい（要配慮個人情報、財産的被害のおそれ、不正目的、**1,000人超**）は**個人情報保護委員会への報告と本人への通知が義務**（2022年〜） |
| **第三者提供** | 個人データを第三者に渡すには、原則として**あらかじめ本人の同意**が必要。例外は ①法令に基づく場合 ②人の生命・身体・財産の保護に必要で同意を得るのが困難な場合 など。提供の**記録の作成・保存**も必要 |
| オプトアウト | 本人が求めたら提供を止めること等を条件に、同意なしで第三者提供できる仕組み。**個人情報保護委員会への届出**が必要。**要配慮個人情報**や、不正取得・オプトアウトで取得したデータには使えない |
| **委託** | 業務の委託に伴って個人データを渡すのは**第三者提供に当たらない**（同意不要）。代わりに委託元に**委託先の監督義務**がある。ほかに**事業承継**（合併など）、**共同利用**も第三者提供に当たらない |
| 開示請求等 | 本人は保有個人データの開示・訂正・利用停止等を請求できる。開示は**電磁的記録での提供**も選べる（2022年〜） |

- **AIの場面での例**:
  - 「商品発送のため」に集めた顧客データを、そのまま**別目的のAI学習**に使う → 利用目的の範囲内かを確認する。範囲外なら同意か目的の見直しが必要。
  - AI開発をベンダーに外注し、顧客データを渡す → **委託**として整理できれば同意不要（ただし委託先の監督が必要。ベンダーが**自社のモデル改善に流用**するなら委託の範囲を超える）。
  - **学習済みモデル**: 学習に個人データを使っても、モデルのパラメータは通常、特定の個人との対応関係がないので**個人情報に当たらない**と整理されている。
- **生成AIの利用**: 個人情報保護委員会は2023年6月に「生成AIサービスの利用に関する注意喚起等」を公表した。事業者がプロンプトに個人データを入力する場合は**利用目的の範囲内**かを十分確認すること、AI事業者（OpenAI）には要配慮個人情報を本人の同意なく取得しないこと等を求めた。

### 越境移転とGDPR

#### 外国にある第三者への提供（越境移転）
- 個人データを**外国にある第三者**へ提供するには、原則として**本人の同意**が必要。同意を得る際には、移転先の国名、その国の個人情報保護制度、移転先が講じる措置の情報を本人に提供する（2022年〜強化）。
- 同意が不要になる例外:
  1. 日本と同等の水準の制度があると認めた国（**EU・英国**）にある第三者への提供
  2. 移転先が日本の事業者と同等の措置を講じる**体制を整備**している場合（契約などで担保する）
- **問われ方**: 「海外のサーバーにデータを置くだけでも常に本人同意が必要」とは限らない。クラウド事業者がデータを取り扱わない（アクセスしない）契約になっていれば、そもそも「提供」に当たらないと整理されることがある。

#### GDPR（一般データ保護規則）
- **一言で**: EUの個人データ保護の規則。**2018年5月25日**に適用開始。各国の国内法を作らなくても直接適用される「規則（Regulation）」で、**ハードロー**（法的拘束力のある規制。→ 10章）の代表例。
- **域外適用**: EU域内に拠点がなくても、**EU域内の人に商品・サービスを提供**したり、その行動を監視（追跡・プロファイリング）したりする日本企業にも適用される。
- **主な権利**: **忘れられる権利**（消去権）、**データポータビリティの権利**（自分のデータを別のサービスへ持ち運ぶ）、**プロファイリングを含む自動化された意思決定のみに基づく決定に服さない権利**（AIだけで重要な決定をされない権利）など。
- **制裁金**: 最も重い違反で **2,000万ユーロ**または**全世界年間売上高の4%**のうち**高い方**が上限。
- **十分性認定**: EUが「日本は十分な保護水準を持つ」と認める決定（**2019年1月**）。日本も同時にEUを指定した（**相互認証**）。これにより、EUから日本へ個人データを移転しやすくなった。
- **個人データの範囲**: GDPRでは **IPアドレスやCookie識別子** なども個人データになりうる。日本の「個人情報」より範囲が広い点が比較で問われる。

### 2026年（令和8年）改正（成立済み・施行前）

「3年ごと見直し」を受けた改正法が **2026年7月10日に成立、7月17日に公布**された。施行は大部分が**公布から2年以内**の政令で定める日で、2026年10月時点では政令・規則・ガイドラインの整備中（まだ施行されていない）。

| 改正項目 | 内容 | AIとの関係 |
|---|---|---|
| **統計作成等の特例** | **統計情報等の作成にのみ**利用される場合、①個人データの**第三者提供**、②**公開されている要配慮個人情報の取得**について、本人の同意を不要にする | 個人情報保護委員会の資料では「統計作成等であると整理できる**AI開発**等」も含むとされる。生成AIの事前学習のように、特定の個人ではなく**集団の傾向を学ぶ**目的が想定されている。目的外利用の禁止などの担保措置は委員会規則で定める予定 |
| 同意規律の見直し | 本人の権利利益を害さないことが明らかな取扱い（契約の履行に必要な場合など）は同意不要に | ― |
| **顔特徴データ等** | 取扱いに関する一定の事項の周知を義務化、利用停止等の請求の要件を緩和、**オプトアウトによる第三者提供を禁止** | 顔認識AI・カメラ画像の利活用（→ 10章「カメラ画像利活用ガイドブック」） |

| **課徴金制度** | 重大な違反で利益を得た場合に、個人情報保護委員会が**課徴金の納付**を命じる（不適正利用、不正取得、違法な第三者提供、統計特例の違反などが対象。対象者が**1,000人規模**の事案などに限定） | 違法に集めたデータでのAI開発などに経済的な制裁 |
| 罰則の強化 | 不正な提供・盗用への罰則の拡大、法定刑の引き上げ、詐欺などによる不正取得への罰則の新設 | ― |

## 9-2 著作権法

### 著作権の基本

| 用語 | 一言で | ポイント |
|---|---|---|
| **著作物** | **思想または感情を創作的に表現したもの**であって、文芸・学術・美術・音楽の範囲に属するもの（著作権法2条1項1号） | **アイデア・事実・データそのもの**は保護されない（表現だけを守る）。プログラムも著作物だが、**プログラム言語・規約（プロトコル）・解法（アルゴリズム）**は保護されない |
| **創作性** | 作者の**個性**が表現に表れていること | 高い芸術性や独創性は不要。子どもの絵でもよい。逆に、誰が書いても同じになるありふれた表現には創作性がない |
| **著作権** | 著作物を無断で複製・公衆送信・翻案（改変）などされない権利の束 | **創作した時点で自動的に発生**（登録不要＝**無方式主義**）。存続期間は原則**著作者の死後70年**。ほかに公表権・氏名表示権・同一性保持権などの**著作者人格権**がある |
| **著作権侵害** | 権利者の許諾も権利制限規定（例外）もなく、著作物を利用すること | 既存の著作物に **①類似性**（創作的表現が似ている）と **②依拠性**（既存の著作物をもとにした）の両方があると侵害になる。偶然似ただけ（依拠なし）なら侵害ではない |

- **職務著作（法人著作）**: 会社の発意で、従業員が職務上作成し、会社名義で公表するもの（プログラムは公表名義を問わない）は、**会社が著作者**になる。特許の職務発明（発明者は従業員）との違いが比較で問われる（→ 9-3）。
- **データやデータベース**: 数値の羅列などのデータそのものは著作物ではない。ただし、情報の**選択や体系的な構成に創作性**があるデータベースは「データベースの著作物」として保護される。
- **学習済みモデル**: 推論プログラムは「プログラムの著作物」になりうるが、**学習済みパラメータ（重みの数値）**は創作的表現とは言いにくく、著作物と認められない可能性が高い。そのため学習済みモデルは**契約や営業秘密として守る**のが実務の考え方（→ 9-4、9-6）。

### 学習段階と生成・利用段階を分ける

文化審議会著作権分科会法制度小委員会の **「AIと著作権に関する考え方について」**（**2024年3月15日**取りまとめ、文化庁が公表）は、AIと著作権の関係を **「AI開発・学習段階」と「生成・利用段階」** に分けて整理した。法律そのものを変えたのではなく、**現行法の解釈**を示した文書。2024年7月31日には、立場ごとの取組みをまとめた **「AIと著作権に関するチェックリスト&ガイダンス」**（文化庁著作権課）も公表された。著作権法は、2026年10月時点でAIに関する新たな改正はされていない。

| | AI開発・学習段階 | 生成・利用段階 |
|---|---|---|
| 行為 | 学習データの収集・複製、学習用データセットの作成、学習 | AIで画像・文章を生成し、公開・販売する |
| 基本ルール | **著作権法30条の4**により、**情報解析など「享受」を目的としない利用**は、原則として**権利者の許諾なく**できる | **通常の著作権侵害と同じ**判断（類似性＋依拠性）。AIを使ったかどうかで基準は変わらない |
| 例外・注意点 | ①**享受目的が併存**する場合 ②**著作権者の利益を不当に害する**場合（30条の4ただし書）は許諾が必要 | 既存作品に似た生成物を、**許諾なく公開・販売**すると侵害になりうる |

### 著作権法30条の4（著作物に表現された思想又は感情の享受を目的としない利用）
- **一言で**: 著作物を、その表現を**味わう（享受する）ためではなく**、情報解析などのために使う場合は、**必要と認められる限度で、営利・非営利を問わず**許諾なく利用できる、という規定。
- **成立**: **2018年改正**（2019年1月1日施行）で「柔軟な権利制限規定」として新設された。以前の47条の7（情報解析のための複製）を広げたもの。日本が「機械学習パラダイス」と呼ばれる理由。
- **なぜ**: 情報解析では、作品の表現を人が楽しむわけではないので、権利者が作品から得る利益（対価を払って鑑賞してもらうこと）を害しない。AI・ビッグデータの開発を後押しするため。
- **例外1: 享受目的の併存**（30条の4が使えない）
  - 学習データに含まれる特定の作品の**創作的表現をそのまま出力させる目的**で追加学習する（意図的な「過学習」など）。
  - **RAG**（検索拡張生成。→ 06章）などで、既存の著作物の**創作的表現を出力に含める目的**で、データベース化して使う（このときは**47条の5**などの別の規定の適否を検討する）。
  - なお、**作風・画風**そのものは**アイデア**なので、作風を似せる目的だけでは享受目的とはされない。ただし作風の共通する作品群の創作的表現まで出力させる目的なら享受目的の併存とされうる。
- **例外2: 著作権者の利益を不当に害する場合**（ただし書）
  - **情報解析用に販売されているデータベース**を、買わずに複製して学習に使う。
  - **robots.txt** などの技術的な措置で、AI学習のための収集を防いでいるサイトで、将来データベースとして販売することが推認される場合に、その措置を回避して収集する。
- **注意**: **海賊版**など侵害物と知りながら学習データを集めることは、権利侵害を助長するおそれがあるため、厳に慎むべきとされた（開発者が侵害の責任を問われる可能性を高める）。

### 著作権法47条の5（電子計算機による情報処理の結果提供に付随する軽微利用）
- **一言で**: **所在検索サービス**（検索エンジン）や**情報解析サービス**（論文の剽窃チェックなど）で、結果と一緒に元の著作物の一部を**軽微な範囲**で表示することを認める規定（2018年改正）。
- **AIとの関係**: RAGで回答とともに既存の記事の一部を示すときに、**軽微利用**の範囲かどうかが論点になる。

| | 30条の4 | 47条の5 |
|---|---|---|
| 目的 | 情報解析など、**享受を目的としない**利用 | 検索・解析の**結果を提供する際に付随する**利用 |
| 利用できる量 | 必要と認められる限度（全体の複製も可） | **軽微な**範囲（短い一部など） |
| AIでの典型 | 学習データの収集・学習 | 検索型AI・RAGでの出典の一部表示 |

### AI生成物の著作物性
- **一言で**: AIが**自律的に**生成したもの（人間が簡単な指示を出しただけのもの）は「思想または感情を創作的に表現したもの」に当たらず、**著作物ではない**。人間が**創作的寄与**をして、AIを**道具**として使ったと言える場合は、**その人間が著作者**になる。
- **創作的寄与の判断要素**（「AIと著作権に関する考え方について」）:

| 要素 | 創作的寄与と認められやすい | 認められにくい |
|---|---|---|
| 指示・入力（プロンプト等） | 創作的表現と言える**具体的で詳細な**指示、ラフスケッチなど**創作的な画像の入力** | 長くても、**アイデアにとどまる**指示 |
| 生成の試行回数 | 指示・入力の修正と組み合わせて、試行を重ねる | **回数が多いだけ** |
| 複数の生成物からの選択 | 選択が全体として創作的と評価される場合 | **選ぶだけ**（単なる選択行為） |
| 生成後の加筆・修正 | 人間が創作的な加筆・修正をした**部分**は著作物になりうる | ― |

- **事例**: 2025年11月、生成AIに具体的な指示を繰り返して作られた画像を無断で複製し書籍の表紙に使ったとして、千葉県警が著作権法違反の疑いで男性を書類送検したと報じられた。AI生成画像を著作物と判断して摘発した国内初の例とみられる。
- **海外**: 米国著作権局は、人間の著作者性がない部分は登録できないという立場をとる。
- **問われ方**: 「AIが生成したものには一切著作権が生じない」も「プロンプトを入力すれば必ず著作権が生じる」も**誤り**。「AI自身が著作者になる」は**誤り**（著作者は人間または法人）。

### 生成物による著作権侵害
- **類似性**: 生成物に既存の著作物の**創作的表現**が直接感じ取れるか。作風・画風が似ているだけでは原則として類似性はない。
- **依拠性**:
  - 利用者が既存の著作物を知っていて、それに似せるようにプロンプトを入力した（作品名を入れる、画像を入力する）→ 依拠ありとされやすい。
  - 利用者が既存作品を知らなくても、その作品が**AIの学習データに含まれていた**場合は、通常、**依拠があったと推認**される（開発者・利用者が、学習データの著作物の表現を出力しない技術的な措置を講じていたことなどを示せば否定されうる）。
- **誰が責任を負うか**: 原則は生成・利用した**利用者**。ただし、侵害物を高い頻度で生成する、侵害を防ぐ措置をとっていないなどの事情があれば、**AI開発者・サービス提供者**も侵害の主体として責任を負いうる。
- **権利者がとれる手段**: 差止請求（故意・過失は不要）、損害賠償請求（故意・過失が必要）、刑事罰（故意が必要）。差止めでは、侵害物を生成しないような措置や、学習用データセットからの除去を求められる場合がある。

### 利用規約とライセンス
- **利用規約**: サービス提供者が利用者に示す利用条件。生成AIサービスでは、**入力データを学習に使うか**、**生成物の権利が誰にあるか**、**商用利用の可否**、禁止事項、免責が定められる。著作権法上は許される行為でも、**規約（契約）で禁止**されていれば契約違反になりうる（例: スクレイピングを禁止するサイト規約）。→ 9-7
- **ライセンス**: 著作物を使ってよいという許諾。オープンソースソフトウェア（OSS）やデータセット、公開モデルにも**ライセンス条件**がある。

| ライセンス | 特徴 |
|---|---|
| GPL | 改変・再配布したものにも同じライセンスを適用する義務（**コピーレフト**）。ソースコードの開示が必要になる |
| MIT・BSD・Apache 2.0 | 著作権表示などを残せば商用・改変・再配布が自由（**寛容型**）。Apache 2.0は特許の許諾条項も持つ |
| クリエイティブ・コモンズ（CC） | 作品の利用条件を「表示（BY）」「非営利（NC）」「改変禁止（ND）」「継承（SA）」の組み合わせで示す。データセットでよく使われる |
| 公開モデル独自のライセンス | 重みを公開している基盤モデルでも、利用規模・用途に制限があるものがある（「オープン」でもOSSのライセンスとは限らない） |

- **問われ方**: 「インターネットで公開されているデータセットは自由に商用利用できる」は**誤り**。ライセンスと利用規約を確認する。

## 9-3 特許法と知的財産権

### 知的財産権の全体像

**知的財産権**は、人の知的な創作の成果や、営業上の標識（ブランド）を守る権利の総称。

| 権利 | 守るもの | 発生 | 存続期間 | 所管 |
|---|---|---|---|---|
| **特許権** | 発明（技術的アイデア） | **出願・審査・登録** | **出願から20年**（医薬品などは延長あり） | 特許庁 |
| 実用新案権 | 物の形状・構造の考案（小発明） | 出願・登録（実体審査なし） | 出願から10年 | 特許庁 |
| 意匠権 | デザイン（物品・建築物・画像） | 出願・審査・登録 | 出願から25年 | 特許庁 |
| 商標権 | 商品名・ロゴなどの標識 | 出願・審査・登録 | 登録から10年（**更新可**） | 特許庁 |
| **著作権** | 思想・感情の創作的表現 | **創作時に自動発生** | 原則**著作者の死後70年** | 文化庁 |
| （営業秘密・限定提供データ） | 秘密情報・データ | 要件を満たせば保護（登録なし） | 期限なし | 不正競争防止法（経済産業省） |

- 特許・実用新案・意匠・商標の4つを **産業財産権** という。

### 特許権と発明
- **発明**: **自然法則を利用した技術的思想の創作のうち高度なもの**（特許法2条1項）。
  - 発明に**当たらない**もの: 自然法則そのもの（万有引力の法則）、**単なる発見**、**数学の公式**・ゲームのルールなどの人為的な取り決め、自然法則に反するもの（永久機関）、個人の技能（フォークボールの投げ方）。
  - **AI関連発明**: アルゴリズムそのもの（数学的な手法）は発明に当たらないが、**ソフトウェアによる情報処理がハードウェア資源を用いて具体的に実現**されていれば発明になる。学習済みモデルも「プログラム」として特許の対象になりうる。
- **特許の主な要件**:

| 要件 | 内容 |
|---|---|
| 産業上利用可能性 | 産業で使えること（医療行為そのものなどは対象外） |
| **新規性** | 出願前に**公然知られていない・実施されていない・刊行物やネットで公開されていない**こと（特許法29条1項） |
| **進歩性** | その分野の通常の知識を持つ者（**当業者**）が、既存の技術から**容易に思いつかない**こと（29条2項）。既知の技術の単なる組み合わせ・置き換えは進歩性なし |
| 先願 | 同じ発明なら**先に出願した者**が権利を得る（**先願主義**） |
| 公序良俗 | 公の秩序・善良の風俗を害さないこと |

- **新規性喪失の例外**: 自分で学会発表などをして公開してしまっても、**公開から1年以内**に手続きをして出願すれば、新規性を失わなかったものとして扱われる（2018年改正で6か月から1年に延長）。
- **問われ方**: 「新規性はあるが進歩性がない」例 → 既存の2つの公知技術を単純に組み合わせただけの発明。「AIのアルゴリズム（数式）そのもの」は特許の対象にならない。

### 発明者 ―― AIは発明者になれない
- **発明者**: 発明の**技術的特徴部分の創作に実際に関与した自然人**。単に課題を与えた人、資金を出した人、指示どおりに実験しただけの補助者、管理者は発明者ではない。
- **DABUS事件**: AI（DABUS）を発明者とした特許出願を、特許庁が却下した事件。**東京地裁（2024年5月）**、**知財高裁（2025年1月30日）** はいずれも「特許法の発明者は**自然人に限られる**」とし、**最高裁が2026年3月に上告を退けて確定**した。米国・英国・欧州特許庁なども同様に、AIを発明者と認めていない。
- **AIを道具として使った発明**: AIを使って生まれた発明でも、人間が技術的特徴の創作に関与していれば、その人が発明者として出願できる。

### 職務発明
- **一言で**: 従業員が、会社の業務範囲で、**現在または過去の職務**として行った発明。
- **仕組み**: 特許を受ける権利は本来**発明者（従業員）**のもの。ただし、契約・勤務規則であらかじめ定めておけば、権利を**最初から会社に帰属**させることができる（2015年改正、2016年施行）。その場合、従業員は**相当の利益**（金銭やその他の経済上の利益）を受ける権利を持つ。会社は、権利を取得しなくても**通常実施権**（無償で使える権利）を持つ。
- **背景**: 青色LED訴訟（2004年の東京地裁判決で約200億円の対価を認定、2005年に約8億円で和解）など、対価をめぐる紛争が相次いだことから、制度の見直しが進んだ。

| | 職務発明（特許法） | 職務著作（著作権法） |
|---|---|---|
| 権利者 | 定めがなければ**従業員**が特許を受ける権利を持つ。規則で定めれば会社に帰属 | 要件を満たせば**会社が著作者**になる |
| 従業員への見返り | **相当の利益**を受ける権利 | 法律上の対価請求権はない |

### 特許と営業秘密のどちらで守るか

| | 特許で守る | 営業秘密で守る |
|---|---|---|
| 内容の公開 | 出願から1年6か月で**公開される** | **公開しない** |
| 保護期間 | 出願から20年で切れる | 秘密である限り**期限なし** |
| 独自開発した他社への効力 | **他社が独自に開発しても排除できる** | 他社が独自に開発・リバースエンジニアリングしたものは**排除できない** |
| 向いているもの | 製品を見れば分かってしまう技術 | 外から分からないノウハウ（学習データの加工方法、ハイパーパラメータ、製造条件） |

## 9-4 不正競争防止法

**不正競争防止法**は、事業者間の**公正な競争**を確保するための法律。特許のような登録制度ではなく、**不正な行為を規制**する形で情報を守る。AIでは、学習データやノウハウを守る手段として重要。

### 営業秘密
- **一言で**: 秘密として管理されている、事業に役立つ、知られていない情報（2条6項）。
- **3要件**:

| 要件 | 内容 | 満たさない例 |
|---|---|---|
| **秘密管理性** | 秘密として管理されていることが、従業員などから**認識できる**程度に管理されている | 誰でも見られる共有フォルダに置いている、「社外秘」の表示もアクセス制限もない |
| **有用性** | 事業活動に**有用**な技術上・営業上の情報 | 脱税などの違法な情報。なお失敗した実験データ（ネガティブ・インフォメーション）も有用性は認められうる |
| **非公知性** | 一般に**入手できない** | 論文やWebで公開済み |

- **例**: 顧客名簿、製造ノウハウ、学習用データセット、学習済みモデルのパラメータ、ハイパーパラメータの設定。
- **保護の内容**: 不正に取得・使用・開示する行為に対して、差止め・損害賠償を請求でき、悪質な場合は刑事罰もある。

### 限定提供データ
- **一言で**: **特定の相手に限定して提供**するために、電磁的に**相当量蓄積・管理**されたデータ（2条7項）。2018年改正で新設（2019年7月施行）。
- **なぜ**: データを**有償で複数の会社に提供**するビジネス（データ販売・共有）では、データを多くの相手に渡すので「秘密」とは言えず、営業秘密として守れなかった。一方、データそのものは著作物でもないことが多い。そこで、**秘密でなくても**不正取得・不正使用から守る仕組みが作られた。
- **3要件**:

| 要件 | 内容 |
|---|---|
| **限定提供性** | 業として**特定の者に提供**している（会員限定・契約者限定） |
| **相当蓄積性** | 電磁的方法で**相当量蓄積**され、価値を持つ |
| **電磁的管理性** | **ID・パスワード、暗号化**などのアクセス制限で管理されている |

- **2023年改正（2024年4月施行）**: 以前は「**秘密として管理されているもの**」を限定提供データから除いていたため、秘密管理されているが営業秘密の要件は満たさないデータが、どちらの保護も受けられない隙間があった。改正で除外の対象を「**営業秘密**」に改め、この隙間を埋めた。
- **問われ方**: 「無償で**誰にでも公開**しているオープンデータ」は限定提供データに**当たらない**（限定提供性がない）。

| | 営業秘密 | 限定提供データ |
|---|---|---|
| 想定 | **社内で秘密**にしている情報 | **社外の特定の相手**に提供するデータ |
| 3要件 | 秘密管理性・有用性・非公知性 | 限定提供性・相当蓄積性・電磁的管理性 |
| 秘密であることが必要か | 必要 | **不要** |
| 刑事罰 | あり | **なし**（差止め・損害賠償のみ） |
| 典型例 | 製造ノウハウ、顧客名簿 | 有償で提供する気象データ、走行データ、POSデータ |

## 9-5 独占禁止法

**独占禁止法**（私的独占の禁止及び公正取引の確保に関する法律）は、**公正かつ自由な競争**を守る法律。所管は**公正取引委員会**。

| 規制 | 内容 | AI・データの場面 |
|---|---|---|
| 私的独占 | 他社を**排除・支配**して市場の競争を実質的に制限する | 必要不可欠なデータやAI基盤へのアクセスを競合他社に拒否する |
| 不当な取引制限（**カルテル**） | 競争する事業者どうしが価格や数量を**取り決める** | **価格設定アルゴリズム**を共有して、結果的に価格をそろえる（デジタル・カルテル） |
| **不公正な取引方法** | 抱き合わせ、排他条件付取引、**優越的地位の濫用**など、**公正な競争を阻害するおそれ**のある行為 | 取引上の立場が強いプラットフォーム事業者が、取引先にデータの無償提供を強いる。自社サービスの優遇 |
| 企業結合規制 | 合併・買収で競争が制限されないかを審査 | データを大量に持つ企業の買収（データの集積による競争への影響） |

### 競争制限と公正競争阻害性
- **競争制限**: 市場における競争が**実質的に制限される**こと。私的独占・不当な取引制限で問われる「市場全体の競争がなくなる」レベルの効果。
- **公正競争阻害性**: **公正な競争を阻害するおそれ**。不公正な取引方法が違法になるかを判断する基準で、競争制限より**手前の段階（おそれ）**で規制できる。
- **AIでの論点**: データやAI基盤（計算資源・基盤モデル）の**囲い込み**、**自社優遇**、**抱き合わせ**、アルゴリズムを使った**協調**、高度専門人材の獲得。公正取引委員会は「生成AIを巡る競争」のディスカッションペーパー（2024年10月）、報告書 ver.1.0（2025年6月）、ver.2.0（2026年4月）で、生成AI市場を**インフラ・モデル・アプリケーション**の層に分けて論点を整理している。
- **関連する法律**: 大手デジタルプラットフォームには、デジタルプラットフォーム取引透明化法（2021年施行）や、スマホソフトウェア競争促進法（2025年12月全面施行）といった個別の法律もある。
- **問われ方**: 「大量のデータを保有していること自体が独占禁止法違反になる」は**誤り**。データの集積そのものではなく、それを使って**競争を制限・阻害する行為**が問題になる。

## 9-6 AI開発委託契約

### AI開発が従来のシステム開発と違う点
経産省の契約ガイドラインは、AI（学習済みモデル）の開発には次の特徴があり、従来の「要件を決めて、その通りに作って納品する」型の契約がなじみにくいとした。

1. 学習済みモデルの内容・性能が、**契約の時点では分からない**ことが多い（やってみないと精度が分からない）
2. 内容・性能が**学習用データセットに左右される**（データはユーザー側が持っていることが多い）
3. 開発に**ノウハウ**が重要（ベンダー側の資産）
4. 生成物（学習済みモデルなど）を**再利用したい需要**がある

### AI・データの利用に関する契約ガイドライン
- **一言で**: 経済産業省が**2018年6月**に公表した、AI開発とデータ取引の契約の考え方とモデル契約書を示したガイドライン。**AI編**と**データ編**に分かれる（2019年12月に1.1版）。法的拘束力はない（**ソフトロー**）。
- **なぜ**: AI開発の契約実務が確立しておらず、ユーザーとベンダーの認識のずれから紛争が起きたり、契約交渉に時間がかかって開発が進まなかったりした。
- **関連する新しい資料**: 経産省は **2025年2月**に、生成AIなどのAIサービスを利用・開発する企業向けの **「AIの利用・開発に関する契約チェックリスト」** を公表した（入力データの扱い、生成物の権利、データの第三者提供など、契約で確認すべき点をまとめたもの）。特許庁・経産省も、スタートアップとの連携向けの**モデル契約書（AI編）**を公表している。

### 探索的段階型の開発

AI開発を**段階に区切り**、各段階の終わりに**次へ進むかを判断**しながら進める方式（07章のPoCも参照）。

```
アセスメント ──→ PoC ──→ 開発 ──→ 追加学習
（できそうか）  （精度が出るか）（作る）   （納品後に再学習）
  NDA         導入検証契約   ソフトウェア開発契約  内容に応じて個別に契約
```

| 段階 | 目的 | 主な契約 | 主な成果物 |
|---|---|---|---|
| ①**アセスメント** | 一定量のデータで、学習済みモデルを作れる**可能性を検証**する | **秘密保持契約（NDA）** | レポートなど |
| ②**PoC** | 学習用データセットで、ユーザーの求める**精度のモデルが作れるか**を検証する | **導入検証契約**（**準委任**型が基本） | レポート、パイロット版の学習済みモデルなど |
| ③**開発** | 実際に学習済みモデルを**生成**する | **ソフトウェア開発契約**（**準委任**型がなじみやすい。成果の内容が明確な部分は請負もありうる） | 学習済みモデルなど |
| ④**追加学習** | 納品後に追加のデータで**再学習**して精度を維持・向上する | 内容に応じて別途合意（再度の開発契約、保守・運用の契約など） | 追加学習済みのモデル（再利用モデル）など |

- **なぜ段階型か**: いきなり大きな契約を結ぶと、「やってみたら精度が出なかった」ときに費用と責任をめぐって紛争になる。小さく試して、**撤退の判断**ができるようにする。
- **問われ方**: 段階の**順序**（アセスメント → PoC → 開発 → 追加学習）、各段階の契約（**アセスメント＝NDA**、**PoC＝導入検証契約**）。

### NDA（秘密保持契約）
- **一言で**: 取引の検討や協議の中で知った**相手の秘密情報を、目的外に使わず、第三者に開示しない**ことを約束する契約。
- **主な条項**: 秘密情報の定義（何が秘密か）、目的外使用の禁止、開示してよい範囲、秘密保持の期間、契約終了時の返還・破棄。
- **AI開発での位置づけ**: アセスメント段階でユーザーがサンプルデータを渡す前に結ぶ。**NDAを結べば営業秘密の秘密管理性を保ちやすい**、という関係もある。

### PoC（概念実証）
- **一言で**: 本格的な開発の前に、**小規模に試して実現可能性や効果を確かめる**段階。プロジェクト上の意味（PoC止まりなど）は07章。
- **契約上のポイント**: 結果が出るかやってみないと分からないので、**完成義務を負わない準委任型**の**導入検証契約**が基本。成果物の権利や、PoCの結果次第で次の段階に進むかどうかを決めておく。

### 請負契約と準委任契約

| | **請負契約** | **準委任契約** |
|---|---|---|
| 約束すること | **仕事の完成**（民法632条） | **事務の処理**（作業の遂行）。完成は約束しない |
| 義務の中心 | 完成した成果物を引き渡す | **善良な管理者の注意（善管注意義務）**をもって作業する |
| 報酬 | 完成した成果物に対して払う | 作業の量（時間）に対して払う**履行割合型**が基本。2020年施行の改正民法で、成果に対して払う**成果完成型**も明文化された |
| 成果物に問題があったとき | **契約不適合責任**（旧・瑕疵担保責任）を負う（修補・代金減額・損害賠償・解除） | 契約不適合責任は**負わない**（善管注意義務に違反していれば責任を負う） |
| AI開発での向き・不向き | 仕様と完成の基準が明確な部分（AIを組み込むシステムの開発など） | 結果が予測しにくい**アセスメント・PoC・モデルの開発** |

- **問われ方**: 「準委任契約では成果物の完成義務を負う」は**誤り**。「AI開発では、目標の精度を必ず達成する請負契約が推奨される」は**誤り**。「成果完成型の準委任なら完成義務がある」も**誤り**（成果に対して報酬を払うだけで、完成を約束するわけではない）。

### 精度保証
- **一言で**: 学習済みモデルが一定の精度（例: 正解率90%以上）を満たすことを**ベンダーが保証する**契約条項。
- **ガイドラインの考え方**: 学習済みモデルの性能は**学習用データ**や**未知の入力**に左右され、ベンダーだけでは制御できない。そのため、ベンダーが**完成や性能を保証することは難しく**、安易に精度を保証させるのは適切でない。代わりに、**段階ごとに目標の精度を確認しながら進める**、精度が出なかったときの扱い（中止・再交渉）を決めておく。
- **問われ方**: 「ベンダーは通常、未知のデータに対する精度を保証すべき」は**誤り**。

### 保守契約
- **一言で**: 納品後のシステムやモデルを動かし続けるための**点検・修正・更新**の契約。
- **AI特有の点**: 運用中に入力データの傾向が変わる（**ドリフト**、→ 07章）と精度が落ちるので、**モニタリング**、**再学習（追加学習）**、それに使うデータの提供を誰が担うか、精度低下が瑕疵（不具合）に当たるかどうかを決めておく。
- **問われ方**: 「納品後にモデルの精度が下がった場合、ベンダーが当然に無償で再学習する義務を負う」は**誤り**。契約で決めた範囲による。

### 学習済みモデルの権利帰属と利用条件

ガイドラインは、AI開発の成果物と中間生成物を次のように分けて考える。

| 生成物 | 中身 | 主な権利 |
|---|---|---|
| 生データ | ユーザーが持つ元のデータ | 著作物でないことが多い（契約・営業秘密で保護） |
| 学習用データセット | 生データを前処理・アノテーションしたもの | データベースの著作物になる場合がある |
| 学習用プログラム | 学習のためのプログラム | プログラムの著作物 |
| **学習済みモデル** | **推論プログラム＋学習済みパラメータ** | 推論プログラムは著作物、パラメータは著作物でない可能性が高い（契約・営業秘密で保護） |
| 再利用モデル・派生モデル | 学習済みモデルに追加学習したもの（再利用モデル）、学習済みモデルの入出力を使って別に作ったもの（**蒸留モデル**など） | 元のモデルの権利が及ぶかは不明確 |
| ノウハウ | 前処理・ハイパーパラメータ調整などの知見 | 営業秘密 |

- **基本の考え方**: 学習済みモデルは、ユーザー（**データ**を提供）とベンダー（**技術・ノウハウ**を提供）の両方の寄与で生まれる。どちらか一方に権利を全部帰属させると、もう一方が再利用できなくなる。そこでガイドラインは、**権利の帰属**だけでなく、**利用条件**（利用目的、利用期間、再利用・他社への提供の可否、追加学習の可否、対価）を**きめ細かく決めること**で双方の利益を調整するよう勧めている。
- **知的財産権が生じない部分**: パラメータやデータのように**知的財産権が成立しない（または成立が不確か）**ものは、「誰に帰属するか」を決めても意味が薄いので、**契約で利用条件を決めて守る**。
- **データ編の3類型**（データ取引の契約）:

| 類型 | 内容 |
|---|---|
| データ提供型 | 一方が持つデータを相手に提供する（ライセンス、譲渡、共同利用） |
| データ創出型 | 複数の当事者が関与して**新たに生まれたデータ**の利用権限を決める（センサーデータなど） |
| データ共用型（プラットフォーム型） | プラットフォームを通じて複数の事業者がデータを共有する |

- **問われ方**: 「学習済みモデルの著作権は常にユーザーに帰属する」「データには所有権があり、提供した側が当然に権利を持つ」は**誤り**。

## 9-7 AIサービス提供契約（SaaS型）

### SaaS（Software as a Service）
- **一言で**: ソフトウェアを利用者の環境にインストールせず、**インターネット経由のサービス**として提供する形態。生成AIのWebサービスやAPIの多くがこれに当たる。
- **SaaS型の特殊性**:
  - 提供者が**多数の利用者に同じサービス**を提供するので、契約は個別交渉ではなく**利用規約**（定型約款）で定めるのが普通。
  - 提供者がサービスを**一方的に更新**する（モデルの更新で出力が変わることがある）。
  - 利用者の**入力データが提供者のサーバーに送られ**、サービスの改善やモデルの学習に使われることがある。
- **契約で確認すべき点**:

| 項目 | 確認すること |
|---|---|
| **データ利用権** | 入力データ・出力データを提供者が**学習や改善に使えるか**、第三者に提供するか、**オプトアウト**（学習に使わせない設定）があるか |
| 生成物の権利 | 生成物の権利・商用利用の可否。第三者の権利を侵害したときの責任の分担 |
| **精度保証**・免責 | 出力の正確性は保証されないのが一般的（ハルシネーション、→ 06章）。SLA（稼働率などのサービス水準）は定められることがある |
| 保守・変更 | モデルの更新・サービス終了時の扱い、データの返還・削除 |
| 秘密情報・個人情報 | 入力データの保存場所（**越境移転**）、委託として整理できるか |

### データ利用権
- **一言で**: サービスの提供で生まれた・受け取ったデータを、**誰が、どの範囲で使えるか**という契約上の権限。
- **なぜ重要か**: データそのものには所有権がなく、著作物でもないことが多いので、法律だけでは扱いが決まらない。**契約で利用範囲を決める**ことが唯一の確実な手段になる。
- **典型例**: 企業向けの生成AIサービスでは「入力データを学習に使わない」ことを規約で約束するものが多い。一方、無料版などでは入力が学習に使われることがある。業務で使う前に規約を確認し、**機密情報・個人情報を入力しない**などの社内ルールを作る。

- 個人情報保護法: 2003年成立／2017年施行の改正で個人識別符号・要配慮個人情報・匿名加工情報、5,000件要件の撤廃／**2022年4月**施行の改正で**仮名加工情報**・個人関連情報、漏えい報告の義務化／**2026年7月**成立の改正で統計作成等（AI開発を含む）の同意不要特例・課徴金（施行は公布から2年以内）

- GDPR: **2018年5月**適用開始、制裁金は**2,000万ユーロか全世界売上高の4%の高い方**／日本とEUの相互の十分性認定: **2019年1月**
- 著作権法30条の4・47条の5: **2018年改正**（2019年1月施行）／「AIと著作権に関する考え方について」: **2024年3月**／チェックリスト&ガイダンス: **2024年7月**
- 著作権の存続期間: **死後70年**／特許権: **出願から20年**／新規性喪失の例外: **1年以内**
- 限定提供データ: 2018年改正で新設（2019年7月施行）、2023年改正（2024年4月施行）で「秘密管理」除外を「営業秘密」除外に変更
- 契約ガイドライン: 経産省 **2018年6月**（AI編・データ編）／契約チェックリスト: **2025年2月**
- DABUS事件: 知財高裁 **2025年1月**（AIは発明者になれない）、最高裁で2026年3月に確定

**対応関係**
- 個人情報 ⊃ 個人データ ⊃ 保有個人データ
- 匿名加工情報 → 復元不可・第三者提供可／仮名加工情報 → 照合で識別可・社内利用・第三者提供不可
- 委託・事業承継・共同利用 → 第三者提供に当たらない（同意不要）
- 学習段階 → 30条の4（享受目的でなければ許諾不要）／生成・利用段階 → 類似性＋依拠性で侵害を判断
- 営業秘密 → 秘密管理性・有用性・非公知性／限定提供データ → 限定提供性・相当蓄積性・電磁的管理性
- 特許の要件 → 産業上利用可能性・新規性・進歩性・先願
- 探索的段階型 → アセスメント（NDA）→ PoC（導入検証契約）→ 開発（ソフトウェア開発契約）→ 追加学習
- 請負 → 完成義務・契約不適合責任あり／準委任 → 完成義務なし・善管注意義務
- 競争制限 → 私的独占・カルテルの基準／公正競争阻害性 → 不公正な取引方法の基準

**ひっかけ注意**
- 死者の情報・法人の情報は個人情報ではない。電話番号・メールアドレスは個人識別符号ではない。
- 労働組合への加盟・性的指向は、日本法の要配慮個人情報の列挙には入っていない（GDPRの特別カテゴリーとの混同に注意）。
- 2022年4月以降、6か月以内に消去する個人データも保有個人データに含まれる。
- 仮名加工情報は第三者に提供できない。匿名加工情報は同意なしで提供できるが、公表・明示が必要。
- 30条の4があっても、享受目的が併存する場合や、情報解析用の有償データベースを無断で使う場合は許諾が必要。
- 作風・画風（アイデア）は著作権で保護されない。ただし、生成物に既存作品の創作的表現が表れていれば侵害になりうる。
- AI生成物でも、人間の創作的寄与があれば著作物になりうる。AI自体は著作者にも発明者にもなれない。
- 著作権は自動発生、特許権は出願・登録が必要。
- 職務発明の発明者は従業員（権利は規則で会社に帰属させられる）。職務著作は会社が著作者。
- 限定提供データは秘密でなくてよく、刑事罰はない。誰にでも無償で公開しているデータは対象外。
- データを大量に持つこと自体は独占禁止法違反ではない。
- AI開発では精度保証を安易に約束しない。PoCは準委任が基本。
- 2026年改正の個人情報保護法は成立済みだが、2026年10月時点では未施行。

### 用語集の記述との相違点
- **要配慮個人情報**: 用語集は例に「**労働組合への加盟状況、性的指向**」を挙げているが、日本の個人情報保護法（法2条3項と施行令）の要配慮個人情報には**含まれない**（人種、信条、社会的身分、病歴、犯罪の経歴、犯罪被害の事実、障害、健康診断等の結果、診療・調剤、刑事・少年事件の手続が対象）。労働組合への加盟は金融分野ガイドラインの「機微情報」、性的指向はGDPRの特別カテゴリーなど別の枠組みのもの。また「取得や**利用**には原則として本人の同意が必要」とあるが、同意が必要とされるのは**取得**（とオプトアウト提供の禁止）であり、利用については通常の利用目的の制限が適用される。
- **保有個人データ**: 用語集は「**6か月以内など短期間で消去されるデータ**…は含まれません」としているが、この除外規定は2020年改正（**2022年4月施行**）で**廃止**され、現在は短期間で消去するデータも保有個人データに含まれる。古い記述。
- **著作権**: 「AI生成物は…基本的に著作権は認められません」は方向として正しいが、判断基準が「人間の**創作的寄与**」であること、「単に試行回数が多い」「単に選んだだけ」では足りないことが書かれていない（文化庁「考え方」）。補足が望ましい。
- **個人情報保護法の最新改正**: 用語集には2026年7月成立の改正（統計作成等の特例、課徴金など）の記述がない。
