# 05 ディープラーニングの要素技術

> 重点分野。04章の「学習の仕組み」の上に載る、**ネットワークの部品（層）と設計の工夫**の章。06章（応用例）に出てくる有名モデルは、ほぼすべてこの章の部品の組み合わせでできている。

## この章で押さえること

- ネットワークの部品は**データの形に合わせて選ぶ**。画像のように「近くの値どうしが関係する」データには **CNN**、文章や音声のように「順番が意味を持つ」データには **RNN**、そして現在はどちらにも使える **Transformer** が主流。
- 多くの部品は「**深くすると学習できない**（勾配消失）」「**パラメータが多すぎる**」という問題への対策として生まれた。正規化層・スキップ結合・LSTM・1×1畳み込みは、すべてこの文脈で理解する。
- 系列モデルの系譜 **RNN → LSTM/GRU → Seq2Seq → Attention → Transformer** は、「前の手法の何が困ったか」を順番に説明できるようにする。
- 計算問題として、**畳み込みの出力サイズ**（(入力 ＋ 2×パディング − フィルタ) ÷ ストライド ＋ 1）と**パラメータ数**が出る。
- 試験では、**正規化の4種類の違い**、**ResNet が深くできる理由**、**Q・K・V の役割**、**データ拡張の手法の見分け（Cutout／Random Erasing／Mixup／CutMix）** がよく問われる。

## 5-1 全結合層とCNNの基本

### 全結合層（と線形関数）
- **一言で**: 前の層の**すべての**ユニットが、次の層の**すべての**ユニットとつながっている層。04章の多層パーセプトロンは全結合層を重ねたもの。
- **中身**: 各つながりに重みがあり、「入力×重みの合計＋バイアス」を計算する。これは**線形関数**（グラフが直線・平面になる、f(x) = ax + b の形の関数）なので、そのあとに非線形の活性化関数を通す（線形関数だけを何層重ねても1つの線形関数と同じになる → 04章 4-2）。
- **パラメータ数**: 入力ユニット数 × 出力ユニット数 ＋ 出力ユニット数（バイアス）。
- **弱点**: 画像をそのまま入れると、パラメータが爆発する。32×32 のカラー画像（32×32×3 ＝ 3,072個の値）を1,000ユニットの全結合層につなぐだけで、約307万個の重みが必要になる。さらに、画像を1列に並べ直すので「上下左右に隣り合う」という位置関係の情報が失われる。
- **現在の使われ方**: CNN の最後で「抽出した特徴 → クラスの判定」を行う部分や、Transformer の内部（5-7 のフィードフォワード層）で使われる。

### 畳み込みニューラルネットワーク（CNN）
- **一言で**: **畳み込み層**と**プーリング層**を重ねて、画像から特徴を自動で取り出すネットワーク。
- **なぜ生まれたか**: 全結合層では画像の位置関係を活かせず、パラメータも多すぎる。そこで、人間の視覚野（小さな範囲にだけ反応する細胞が階層的に並ぶ）をまねて、**小さな範囲ごとに同じフィルタを当てる**構造にした。源流は福島邦彦のネオコグニトロン、ルカンの LeNet（歴史は → 02章）。
- **典型的な構造**:

```
入力画像 → [畳み込み層 → 活性化(ReLU)] → プーリング層 → [畳み込み → ReLU] → プーリング → … → 全結合層 or GAP → ソフトマックス
            └───── 特徴抽出（エッジ → 模様 → 部品 → 物体）─────┘                 └── 分類 ──┘
```

- 浅い層は**エッジや色**のような単純な特徴、深い層ほど**目・車輪のような部品や物体全体**のような抽象的な特徴に反応するようになる。これが04章の「特徴表現学習」の具体的な姿。
- **問われ方**: 「CNN を構成する層」→ 畳み込み層・プーリング層（・全結合層）。「画像認識で CNN が全結合だけのネットワークより優れる理由」→ 位置関係を保てる、パラメータが少ない（疎結合・重み共有）。

### 畳み込み操作・フィルタ（カーネル）・特徴マップ
- **畳み込み操作**: 小さな数値の表（**フィルタ**、別名**カーネル**）を画像の上で少しずつずらしながら当て、重なった部分どうしを掛けて合計した値を出力する処理。
- **特徴マップ**: その出力を並べたもの。フィルタが探している模様がある場所ほど大きな値になる「特徴の地図」。
- **フィルタの値は人が決めるのではなく、学習で決まる**（フィルタの値＝重み）。従来の画像処理では「縦線を検出するフィルタ」などを人が設計していたが、CNN はどんなフィルタが役立つかまで学習する。

**計算の例**（4×4 の入力に 2×2 のフィルタ、ストライド1）

```
入力                フィルタ          特徴マップ（3×3）
1 0 2 1            1 0              左上: 1×1 + 0×0 + 0×0 + 1×1 = 2
0 1 0 2            0 1              右へ1マスずらして同じ計算 …
2 1 1 0                             → 3×3 の出力ができる
1 0 2 1
```

- **チャンネル**: カラー画像は R・G・B の3枚の重なり（3チャンネル）。フィルタも入力と**同じチャンネル数の厚み**を持ち（3×3×3 など）、全チャンネルの結果を足して**1枚の特徴マップ**を作る。
- **フィルタの枚数 ＝ 出力のチャンネル数**。64枚のフィルタを使えば、64チャンネルの特徴マップが出る。

### 疎結合と重み共有（CNN のパラメータが少ない理由）

| | 全結合層 | 畳み込み層 |
|---|---|---|
| つながり方 | 出力の各ユニットが**入力全体**とつながる | 出力の各ユニットが**入力の一部（フィルタの範囲）だけ**とつながる（**疎結合**） |
| 重み | つながりごとに別々の重み | 画像のどの位置でも**同じフィルタ**を使い回す（**重み共有**） |
| 位置関係 | 1列に並べるので失われる | 保たれる |
| パラメータ数 | 非常に多い | 少ない |

- **疎結合のなぜ**: 画像では「近くの画素どうしは関係が深く、遠くの画素とはあまり関係がない」。だから局所だけ見れば十分。
- **重み共有のなぜ**: 「縦線」は画像の左上にあっても右下にあっても同じ縦線。同じ検出器を使い回せる。
- **パラメータ数の計算**: 1つの畳み込み層のパラメータ数 ＝ **フィルタの縦 × 横 × 入力チャンネル数 × フィルタ枚数 ＋ フィルタ枚数（バイアス）**。
  - 例: 3チャンネルの画像に 3×3 のフィルタを64枚 → 3×3×3×64 ＋ 64 ＝ **1,792個**。画像サイズが大きくなっても**増えない**。先ほどの全結合層（約307万個）との差が CNN の強み。

### ストライドとパディング
- **ストライド**: フィルタを**一度に何マス動かすか**（歩幅）。ストライド2なら1マス飛ばしで動くので、出力はおよそ縦横半分になり、計算量も減る。その分、細かい情報は落ちる。
- **パディング**: 畳み込みの前に、入力の**周りに余白**（多くは0。**ゼロパディング**）を付け足すこと。
  - **なぜ必要か**: パディングなしだと、①畳み込むたびに特徴マップが小さくなり、深い層を重ねられない。②画像の**端の画素**はフィルタが当たる回数が少なく、情報が軽視される。
  - フィルタサイズが F（奇数）のとき、パディングを (F − 1) ÷ 2 にしてストライド1で畳み込むと、**出力サイズが入力と同じ**になる（3×3 ならパディング1、5×5 ならパディング2）。

### 出力サイズの計算（計算問題が出る）

**公式**（縦・横それぞれで計算する）

```
出力サイズ ＝ (入力サイズ ＋ 2 × パディング − フィルタサイズ) ÷ ストライド ＋ 1
```

- **意味**: 余白を足した幅（入力＋2×パディング）から、フィルタが置ける位置が何か所あるかを数えている。最初の1か所（＋1）と、そこから**動ける距離**（入力＋2P − F）を歩幅（S）で割った回数の合計。
- パディングは**両側**に付くので **2倍**する。ここが一番のひっかけ。
- 割り切れないときは**切り捨て**（はみ出した位置にはフィルタを置かない）。

| 例 | 入力 | フィルタ | パディング | ストライド | 計算 | 出力 |
|---|---|---|---|---|---|---|
| ① 基本 | 32 | 5 | 0 | 1 | (32 + 0 − 5) ÷ 1 + 1 | **28** |
| ② サイズを保つ | 28 | 3 | 1 | 1 | (28 + 2 − 3) ÷ 1 + 1 | **28** |
| ③ ストライド2 | 7 | 3 | 0 | 2 | (7 + 0 − 3) ÷ 2 + 1 | **3** |
| ④ AlexNet の1層目 | 227 | 11 | 0 | 4 | (227 − 11) ÷ 4 + 1 | **55** |
| ⑤ ストライド2・パディング1 | 224 | 3 | 1 | 2 | (224 + 2 − 3) ÷ 2 + 1 ＝ 111.5 + 1 → 切り捨て | **112** |
| ⑥ プーリング 2×2 | 28 | 2 | 0 | 2 | (28 − 2) ÷ 2 + 1 | **14** |

- **出力の形は「縦 × 横 × フィルタ枚数」**。例えば ① でフィルタを6枚使えば、出力は 28×28×6。チャンネル数は入力のチャンネル数ではなく**フィルタの枚数**で決まる。
- プーリングも同じ公式で計算できる（⑥）。2×2、ストライド2 のプーリングは縦横を**半分**にする。
- **解き方のコツ**: 公式に入れる前に「パディングを2倍したか」「ストライドで割ってから＋1 したか（＋1 してから割っていないか）」を確認する。

### 受容野
- **一言で**: ある出力の1マスが、**元の入力画像のどの範囲を見ているか**。
- **深さとの関係**: 3×3 の畳み込みを2回重ねると、2層目の1マスは入力の 5×5 の範囲を、3回重ねると 7×7 を見ている。層を深くするほど受容野が広がり、大きな物体や全体の文脈をとらえられる。
- **小さいフィルタを重ねる利点**（VGG の考え方 → 06章）: 3×3 を2回（パラメータ 9＋9＝18 × チャンネル数）は、5×5 を1回（25 × チャンネル数）と同じ受容野で、パラメータが少なく、間に活性化関数を2回挟めるので表現力も高い。

## 5-2 プーリングと不変性

### 特徴集約とプーリング
- **一言で**: 特徴マップを小さな領域（2×2 など）に区切り、各領域を**1つの代表値**にまとめて縮小する処理（**特徴集約**）。これを行う層を**プーリング層**という。
- **なぜ**: ①データを小さくして計算量を減らす。②多少の**位置のずれ**があっても同じ値が出るようにする（不変性）。③パラメータを持たないので過学習の原因にならない。

| | 何を取るか | 性質 | 例（2×2 の領域に 1, 5, 3, 2） |
|---|---|---|---|
| **最大値プーリング**（Max Pooling） | 領域の**最大値** | 一番強く反応した特徴を残す。CNN の中間層で最もよく使う | **5** |
| **平均値プーリング**（Average Pooling） | 領域の**平均値** | 全体を滑らかに要約する。ノイズに強い | **2.75** |
| **グローバルアベレージプーリング**（GAP） | 特徴マップ**1枚全体**の平均 | 1チャンネルを1つの値にする。全結合層の代わりに使う | — |

- **プーリング層には学習するパラメータ（重み）がない**。決まった計算（最大値・平均）をするだけ。畳み込み層との違いとしてよく問われる。

### グローバルアベレージプーリング（GAP）
- **一言で**: 各チャンネルの特徴マップ全体を平均して、**1チャンネル＝1つの数値**にまとめる。7×7×512 の特徴マップなら、512個の数値になる。
- **なぜ生まれたか**: CNN の最後の全結合層はパラメータが非常に多く（AlexNet や VGG ではパラメータの大半が全結合層）、過学習の原因にもなっていた。GAP はパラメータを持たずに出力を小さくできる。Network in Network（2013年）で提案され、GoogLeNet や ResNet で採用された（→ 06章）。
- **おまけの利点**: 入力画像のサイズが変わっても、出力の長さはチャンネル数で決まるので同じになる。また、Grad-CAM などの「どこを見て判断したか」の可視化（→ 06章）とも相性がよい。

### 不変性の獲得
- **一言で**: 物体が画像の中で**少し動いても**、同じように認識できる性質。
- **どこから来るか**: 
  - 畳み込みは、物体が動くと特徴マップ上の反応も同じだけ動く（入力の移動に応じて出力も移動する性質）。
  - その後のプーリングが「領域内のどこで反応したか」を気にしないので、**小さな位置ずれ**が吸収される。
- **注意**: CNN の構造だけで得られるのは主に**小さな平行移動**への強さ。**回転や大きな拡大縮小**への強さは構造からは得にくく、5-9 のデータ拡張で補うのが普通。
- **問われ方**: 「プーリングの効果」→ 位置ずれへの頑健性（ロバスト性）、計算量の削減、パラメータを持たない。

## 5-3 特殊な畳み込み

### 1×1畳み込み（Pointwise Convolution）
- **一言で**: 1×1 のフィルタを使う畳み込み。縦横の範囲は見ずに、**同じ位置のチャンネルどうしを混ぜる**。
- **なぜ使うか**: フィルタの枚数を入力チャンネル数より少なくすると、縦横のサイズを変えずに**チャンネル数だけを減らせる**（次元削減）。その後の重い 3×3 や 5×5 の畳み込みの計算量を大きく減らせる。
- **使われる場所**: GoogLeNet の Inception モジュール（→ 06章）、ResNet のボトルネック構造（5-5）、下の Depthwise Separable Convolution の後半。

### Dilated Convolution（Atrous Convolution）
- **一言で**: フィルタの要素の間に**すき間を空けて**当てる畳み込み。「Dilated＝広げた」「Atrous＝穴のあいた（フランス語の à trous）」。
- **なぜ**: 受容野を広げたいとき、フィルタを大きくするとパラメータが増え、プーリングで縮小すると細かい位置情報が失われる。すき間を空ければ、**パラメータ数・計算量を増やさず、解像度も落とさずに**広い範囲を見られる。
- **広さの計算**: 3×3 のフィルタに1マスずつすき間（拡張率2）を空けると 5×5 の範囲、拡張率4なら 9×9 の範囲を見る。重みは9個のまま。
- **使われる場所**: ピクセル単位で領域を分ける**セマンティックセグメンテーション**（DeepLab → 06章）、音声生成の **WaveNet**（→ 06章）。
- **問われ方**: 「パラメータを増やさずに受容野を広げる手法」→ Dilated Convolution。

### Depthwise Separable Convolution
- **一言で**: 通常の畳み込みを、①**Depthwise**（チャンネルごとに別々の1枚のフィルタで縦横方向だけ畳み込む）と ②**Pointwise**（1×1畳み込みでチャンネルを混ぜる）の**2段階に分けて**、計算量を大幅に減らす方法。
- **なぜ**: 通常の畳み込みは「縦横の空間方向」と「チャンネル方向」を同時に処理するため重い。2つを分けても、精度をあまり落とさずに済むことがわかった。
- **どれくらい軽くなるか**（3×3、入力64チャンネル → 出力128チャンネルの例）

| | パラメータ数（バイアスを除く） |
|---|---|
| 通常の畳み込み | 3×3×64×128 ＝ **73,728** |
| Depthwise（3×3×64）＋ Pointwise（1×1×64×128） | 576 ＋ 8,192 ＝ **8,768**（約1/8） |

- **使われる場所**: スマートフォンなど向けの軽量モデル **MobileNet**（→ 06章）、Xception。
- **問われ方**: 「MobileNet で計算量を削減するために使われる手法」→ Depthwise Separable Convolution。

| 畳み込み | 目的 | キーワード |
|---|---|---|
| 1×1畳み込み | チャンネル数を減らす（次元削減） | Inception、ボトルネック |
| Dilated | パラメータを増やさず受容野を広げる | すき間、セグメンテーション、WaveNet |
| Depthwise Separable | 計算量・パラメータを減らす | 2段階、MobileNet |

（補足）セグメンテーションなどで、小さくなった特徴マップを**拡大**する方向の畳み込みを**転置畳み込み**（逆畳み込みとも呼ばれる）という。使い方は06章の FCN・U-Net で触れる。

## 5-4 正規化層

### 正規化層とは
- **一言で**: 層の途中でデータの値を「**平均0・分散1**」にそろえ直す層。そろえたあと、学習可能な2つのパラメータ（スケール γ とシフト β）で、必要なら元の幅に戻せるようにしておく。
- **なぜ必要か**: 学習中は前の層の重みが変わり続けるので、後ろの層に届く値の分布（平均やばらつき）もずれ続ける。後ろの層は「動く的」を追い続けることになり、学習が遅く不安定になる（この現象を**内部共変量シフト**と呼んだ）。値の幅がそろうと、活性化関数の勾配が小さくなる領域に入りにくくなり、**勾配消失の対策**にもなる。

### 4種類の違い（何の範囲で平均・分散を取るか）

データを「バッチ内の件数 N × チャンネル C × 縦横 H×W」の箱として考える。

```
            バッチ正規化        レイヤー正規化       インスタンス正規化      グループ正規化
           (チャンネルごとに、  (1件ごとに、        (1件・1チャンネル     (1件ごとに、チャンネルを
            バッチ全体で)        全チャンネルで)      ごとに)               グループに分けて)
 範囲:      N × H × W           C × H × W          H × W                (C/G) × H × W
```

| | 平均・分散を取る範囲 | バッチサイズへの依存 | 主な用途 | 提案 |
|---|---|---|---|---|
| **バッチ正規化** | ミニバッチ内の**全データ**の、同じチャンネル | **する** | CNN 全般 | 2015年、イオッフェとセゲディ（Google） |
| **レイヤー正規化** | **1件のデータ**の全チャンネル（全特徴量） | しない | **RNN、Transformer** | 2016年、バ、キロス、ヒントン |
| **インスタンス正規化** | **1件のデータの1チャンネル** | しない | **スタイル変換**（画像の画風を変える） | 2016年、ウリヤノフら |
| **グループ正規化** | 1件のデータの**チャンネルのグループ** | しない | **小さいバッチ**しか使えない CNN（物体検出・高解像度画像） | 2018年、ウーとヒー |

### バッチ正規化
- **一言で**: ミニバッチの中の全データで、チャンネル（全結合層ならユニット）ごとに平均と分散を計算して正規化する。
- **効果**: 学習が速く安定する、大きめの学習率を使える、重みの初期値に敏感でなくなる、勾配消失を抑える、軽い正則化の効果（過学習の抑制）もある。
- **弱点**: 
  - **バッチサイズが小さい**と、平均・分散の推定が不安定になる。
  - 推論時は1件ずつ入ることもあるので、**学習中に記録しておいた平均・分散（移動平均）**を使う。学習時と推論時で動作が違う点が出題される。
  - 系列の長さがデータごとに違う **RNN** では使いにくい。
- **問われ方**: 「バッチ正規化はどの範囲で正規化するか」→ ミニバッチ単位。「ドロップアウトと同様に、学習時と推論時で動作が変わるもの」→ バッチ正規化（推論時は学習時の統計量を使う）。

### レイヤー正規化・インスタンス正規化・グループ正規化
- **3つとも生まれた理由は同じ**: バッチ正規化の「**バッチサイズに依存する**」弱点を避けるため、**1件のデータの中だけ**で平均・分散を取る。
- **レイヤー正規化**: 1件の全特徴量でそろえる。系列の長さや時刻に関係なく使えるので RNN に向き、**Transformer の標準部品**になった。
- **インスタンス正規化**: 画像1枚・1チャンネルの中でそろえる。画像ごとの明るさ・コントラストのような「画風」の情報を消すので、**スタイル変換**で効果的。
- **グループ正規化**: レイヤー正規化（全チャンネルを1つにまとめる）とインスタンス正規化（1チャンネルずつ）の**中間**。**グループ数1ならレイヤー正規化、グループ数＝チャンネル数ならインスタンス正規化**と同じになる。
- **問われ方**: 「Transformer で使われる正規化」→ レイヤー正規化。「スタイル変換」→ インスタンス正規化。「バッチサイズが小さいときにバッチ正規化の代わりに使い、チャンネルをグループに分ける」→ グループ正規化。

## 5-5 スキップ結合とResNet

### 逐次的な情報処理と「深くすると悪くなる」問題
- **逐次的な情報処理**: 各層が前の層の出力だけを受け取り、バケツリレーのように順番に処理する、普通のネットワークの流れ。
- **問題**: 層を増やすほど、信号も勾配も**長い経路**を通る。伝言ゲームのように、途中で情報が薄まる（勾配消失）。
- **劣化問題**: ReLU やバッチ正規化を使っても、単純に層を増やしただけのネットワーク（例: 56層）は、浅いネットワーク（例: 20層）より**訓練データでの誤差まで大きく**なった。過学習なら訓練誤差は小さいはずなので、これは過学習ではなく「**深いネットワークをうまく最適化できない**」問題。
- **考え方のヒント**: 理屈の上では、深いネットワークは「追加した層が何もしない（入力をそのまま出す＝恒等写像）」ように学習すれば、浅いネットワークと同じ性能は出せるはず。ところが、非線形の層の積み重ねで「何もしない」を正確に学ぶのは意外に難しい。

### スキップ結合（スキップ接続、ショートカット接続）
- **一言で**: ある層への入力を、途中のいくつかの層を**飛び越えて**後ろに直接渡し、その層たちの出力に**足し合わせる**つなぎ方。

```
        x ─────────────────────────┐  （スキップ結合: そのまま運ぶ）
        │                          │
        ▼                          ▼
   [畳み込み → BN → ReLU → 畳み込み → BN] ── F(x) ──→ (＋) ──→ ReLU ──→ 出力 y = F(x) + x
```

- この「層のかたまり＋スキップ結合」を**残差ブロック**と呼ぶ。

### ResNet（Residual Network、残差ネットワーク）
- **一言で**: 残差ブロックを積み重ねたCNN。2015年にマイクロソフト・リサーチの**カイミン・ヒー（Kaiming He）**らが提案し、**ILSVRC 2015 で優勝**した。**152層**という、それまで（GoogLeNet 22層、VGG 19層）より桁違いに深いネットワークを学習でき、誤り率（top-5）は約3.6%で、人間の目安とされる約5%を下回った。

**なぜ「残差」を学ぶと楽になるか（順伝播の見方）**
- 本来学びたい変換を H(x) とする。普通の層は H(x) そのものを学ぶ。残差ブロックでは y = F(x) + x なので、層が学ぶのは **F(x) ＝ H(x) − x（入力との差分＝残差）** だけになる。
- もし「この層では何もしなくてよい」なら、**F(x) ＝ 0**（重みを0に近づける）だけで済む。恒等写像を一から作るよりずっと簡単。
- 多くの層では最適な変換が「入力を少し修正する」程度なので、差分だけを学ぶ方が効率がよい。

**なぜ勾配消失を防げるか（逆伝播の見方）**― 重要
- y = F(x) + x を x で微分すると、**∂y/∂x ＝ ∂F/∂x ＋ 1**。
- 誤差逆伝播では、後ろから来た勾配にこの値を掛けて前の層へ渡す（連鎖律 → 04章 4-5）。普通の層なら ∂F/∂x だけを掛けるので、1より小さい値を何十回も掛けると勾配は0に近づく。
- スキップ結合があると、**「＋1」の経路**があるので、F の部分の勾配がどれだけ小さくても、**勾配がそのまま（1倍で）前の層へ届く道**が必ず残る。たくさんのブロックを重ねても、入力層近くまで勾配が減衰せずに流れる。
- たとえるなら、各駅停車の線路（層を1つずつ通る道）に加えて**特急の線路**（スキップ結合）を敷いたようなもの。どれだけ駅が多くても、特急の線路を通れば始発駅まで情報が届く。

**ほかの見方（補足）**: スキップ結合があると、信号の通り道が「ブロックを通る／飛ばす」の組み合わせで大量にできる。ResNet は、長さの違う多数の浅いネットワークを合わせた**アンサンブルのようにふるまう**、という解釈もある。

### ボトルネック構造
- **一言で**: 残差ブロックの中を **1×1（チャンネルを減らす）→ 3×3（本来の処理）→ 1×1（チャンネルを戻す）** の3層にして、計算量を減らす構造。瓶の首（ボトルネック）のように途中が細くなる。
- **なぜ**: 層を50層・101層・152層と増やすと、3×3 の畳み込みを多チャンネルのまま重ねるのは重すぎる。チャンネルを一度絞ってから 3×3 を行えば大幅に軽くなる。
- **例**（256チャンネルの入出力）: 1×1 で64に減らす（256×64）→ 3×3 で64→64（3×3×64×64）→ 1×1 で256に戻す（64×256）。合計 約7万個。256チャンネルのまま 3×3 を2回重ねると 約118万個なので、**約17分の1**。
- ResNet-50 以上の深いモデルはボトルネック構造を使う。

### スキップ結合のその後
- スキップ結合は CNN に限らず、**Transformer の各層**（5-7）にも入っている。現在の大規模モデルが何十層も重ねられるのはこの仕組みのおかげ。
- ResNet の発展形（Wide ResNet: 幅を広げる、DenseNet: 前のすべての層の出力をつなぐ など）は → 06章。
- **問われ方**: 「ResNet の特徴」→ スキップ結合、残差学習、勾配消失の緩和、非常に深い（152層）。「ボトルネック構造で 1×1 畳み込みを使う目的」→ チャンネル数を減らして計算量を削減する。

## 5-6 RNNとその改良（系列データの扱い）

### 時系列データと再帰層
- **時系列データ**（系列データ）: 気温の推移、株価、音声、文章のように、**並び順に意味がある**データ。順番を入れ替えると意味が変わる。長さもデータごとに違う。
- **全結合層や CNN が苦手な理由**: 入力の長さが固定で、「さっき何を見たか」を覚えておく仕組みがない。
- **再帰層**（リカレント層）: 前の時刻の自分の出力（記憶）を、**次の時刻の入力と一緒に**受け取るループを持つ層。

### RNN（リカレントニューラルネットワーク）
- **一言で**: 再帰層を持ち、**隠れ状態**（それまでの入力の要約＝記憶）を次の時刻へ受け渡しながら、系列を1つずつ順番に処理するネットワーク。
- **仕組み**: 時刻 t の隠れ状態 ＝ 活性化関数（tanh など）（今の入力 × 重み ＋ 前の隠れ状態 × 重み ＋ バイアス）。**すべての時刻で同じ重みを使い回す**（CNN が位置で重みを共有するのと同じ発想を、時間方向で行っている）。

```
ループで描くと:            時間方向に展開すると:
                          h0 → [RNN] → h1 → [RNN] → h2 → [RNN] → h3
  ┌──┐                           ↑              ↑              ↑
  ▼  │                          x1             x2             x3
 [RNN]─┘ h                       （3つの [RNN] はすべて同じ重み）
  ↑
  x
```

- **得意なこと**: 文章生成、音声認識、時系列予測など。入力の長さが違っても処理できる。
- **弱点**: 
  - **長期依存関係**（ずっと前の情報が今の判断に必要な関係）を学べない。時間をさかのぼるほど勾配が消える（下の BPTT を参照）。
  - 1時刻ずつ順番に計算するので、**並列化できず学習が遅い**（後の Transformer で解決）。

### Elmanネットワークと Jordanネットワーク（初期の単純なRNN）

| | 次の時刻に戻す値 | 提案 |
|---|---|---|
| **Jordanネットワーク** | **出力層**の値 | 1986年、ジョーダン |
| **Elmanネットワーク** | **隠れ層**の値 | 1990年、エルマン |

- どちらも、戻した値を**文脈層**（コンテキスト層）に一時保存し、次の時刻の入力と一緒に使う。現在の RNN は Elman 型（隠れ状態を受け渡す）が基本形。
- **覚え方**: 「**E**lman は中（隠れ層）、**J**ordan は外（出力層）」。

### BPTT（Backpropagation Through Time、通時的誤差逆伝播法）
- **一言で**: RNN を時間方向に展開して「時刻の数だけ層がある深いネットワーク」とみなし、普通の誤差逆伝播法を**時間をさかのぼって**適用する学習方法。
- **なぜ勾配消失・爆発が起きやすいか**: 展開すると、**同じ重み**を時刻の数だけ掛け合わせることになる。100時刻さかのぼれば、ほぼ同じ値を100回掛ける。その値が1より少し小さければ勾配は0に（**勾配消失**）、1より少し大きければ急激に大きく（**勾配爆発**）なる。普通の深いネットワークより極端になりやすい。
- **対策**: 勾配爆発には**勾配クリッピング**（勾配の大きさに上限を設ける → 04章）。勾配消失には **LSTM・GRU**（下）。長すぎる系列は、一定の長さで区切ってさかのぼる **Truncated BPTT** も使われる。

### LSTM（Long Short-Term Memory）
- **一言で**: RNN に「**セル**」という長期記憶の通り道と、情報の出し入れを調整する**ゲート**を加え、長期依存関係を学べるようにしたもの。1997年に**ホッフライター（Hochreiter）とシュミットフーバー（Schmidhuber）**が提案。
- **なぜ生まれたか**: 単純な RNN は、BPTT で勾配を時間方向に何度も掛け算するので、数十時刻前の情報をほとんど学べなかった。
- **名前の意味**: 「長い短期記憶」。RNN の隠れ状態（短期記憶）を**長く保てる**ようにした、という意味。

**中の仕組み**

```
          忘却ゲート       入力ゲート
             f              i × 候補(tanh)
             │                │
 c(t-1) ──→ (×) ──────────→ (＋) ──────────────→ c(t)   ← セル（CEC）: 記憶の通り道
                                    │
                                  tanh
                                    │
                         出力ゲート o → (×) ──────→ h(t)  ← 隠れ状態（出力）
```

| 部品 | 役割 | たとえ |
|---|---|---|
| **セル**（記憶セル、**CEC**: Constant Error Carousel） | 長期の記憶を運ぶ通り道。値を**掛け算ではなく足し算**で更新する | ベルトコンベア |
| **忘却ゲート** | 前の記憶をどれだけ**残すか**（0＝全部忘れる、1＝全部残す） | 古いメモを捨てる |
| **入力ゲート** | 新しい情報をどれだけ記憶に**書き込むか** | 新しいメモを書く |
| **出力ゲート** | 記憶のどれだけを今の**出力（隠れ状態）に出すか** | メモのどこを読み上げるか |

- ゲートは**シグモイド関数**（出力0〜1）で「どれだけ通すか」の割合を出し、値に掛ける。書き込む候補の値には **tanh** を使う。
- **なぜ勾配消失を防げるか**: セルの更新は「前の記憶 × 忘却ゲート ＋ 新しい情報」という**足し算**の形。忘却ゲートが1に近ければ、勾配は**ほぼそのまま**過去へ流れる（同じ値を何度も掛けて小さくなる、ということが起きにくい）。誤差を一定に保ったまま回し続けるので「Constant Error Carousel（誤差を一定に回し続ける回転木馬）」と呼ぶ。ResNet のスキップ結合の「＋1 の経路」と、**足し算で勾配の通り道を作る**という点で発想が同じ。
- **歴史の補足**: 1997年の最初の LSTM には忘却ゲートがなく（CEC ＋ 入力ゲート ＋ 出力ゲート）、**忘却ゲートは2000年ごろにゲルス（Gers）らが追加**した。現在「LSTM」と言えば、3つのゲートを持つこの形を指す。
- **弱点**: パラメータが多く計算が重い。順番に処理するので並列化できない点は RNN と同じ。

### ゲート機構
- **一言で**: 0〜1 の値で「どれだけ通すか」を調整する門。シグモイド関数の出力を情報に掛けることで実現する。
- LSTM（入力・忘却・出力の3つ）と GRU（更新・リセットの2つ）の中核。**何を覚え、何を忘れるか**をデータから学習する。

### GRU（Gated Recurrent Unit）
- **一言で**: LSTM を簡略化したもの。2014年に**チョ（Kyunghyun Cho）**らが提案。
- **違い**: 

| | LSTM | GRU |
|---|---|---|
| ゲート | **3つ**（入力・忘却・出力） | **2つ**（**更新ゲート**・**リセットゲート**） |
| 記憶の持ち方 | **セル**と隠れ状態の2本立て | 隠れ状態**だけ**（セルがない） |
| パラメータ数 | 多い | 少ない（計算が軽く、学習が速い） |
| 性能 | タスクによってほぼ同等 | |

- **更新ゲート**: 前の状態をどれだけ残し、新しい状態をどれだけ取り込むかを1つで決める（LSTM の忘却ゲートと入力ゲートを1つにまとめた役割）。
- **リセットゲート**: 新しい状態の候補を作るときに、前の状態をどれだけ使うか（どれだけ忘れるか）を決める。
- **問われ方**: 「GRU のゲート」→ 更新ゲートとリセットゲート。「忘却ゲート」「出力ゲート」は LSTM の用語なので、GRU の説明に入っていたら誤り。

### 双方向RNN（Bidirectional RNN）
- **一言で**: 系列を**前から読む RNN** と**後ろから読む RNN** の2つを組み合わせ、各時刻で両方の結果をつなげて使う。1997年にシュスターとパリワルが提案。
- **なぜ**: 文章の単語の意味は、前だけでなく**後ろの文脈**でも決まる（「はし」が「橋」か「箸」かは後ろを読まないとわからない）。
- **使えない場面**: 未来の入力を先に知っている必要があるので、**リアルタイムの予測**や、**文章を先頭から1語ずつ生成**するタスクには使えない。文章全体が手元にある分類・タグ付け・翻訳のエンコーダ向き。
- LSTM を双方向にしたもの（BiLSTM）は ELMo（→ 06章）で使われた。

### Seq2Seq（Sequence-to-Sequence）
- **一言で**: 系列を別の系列に変換するモデル。入力を読む**エンコーダ**（RNN/LSTM）と、出力を作る**デコーダ**（RNN/LSTM）をつないだ**エンコーダ・デコーダ構造**。2014年にサツキーバー（Sutskever）ら（Google）が提案（同時期にチョらも同様のモデルを提案）。
- **なぜ**: 翻訳のように、**入力と出力の長さが違う**（日本語5語 → 英語7語）タスクを、1つのニューラルネットワークでまるごと学習したかった。
- **流れ**: 

```
エンコーダ:  私 → は → 猫 → が → 好き      →  最後の隠れ状態（文全体の意味を詰めた固定長ベクトル）
                                                         │
デコーダ:                              <開始> → I → like → cats → <終了>
                                       （1語出すたびに、それを次の入力にする）
```

- **弱点（Attention が生まれた理由）**: 入力文がどれだけ長くても、デコーダに渡すのは**1本の固定長ベクトル**だけ。長い文になるほど情報が入りきらず、翻訳の精度が大きく落ちた。
- **用途**: 機械翻訳、文書要約、対話、音声認識など。

### 教師強制（Teacher Forcing）
- **一言で**: デコーダの学習時に、1つ前の時刻で**モデル自身が出した予測**ではなく、**正解の単語**を次の入力として与える方法。
- **なぜ**: 学習の初めはモデルの予測がでたらめなので、それを次の入力にすると誤りが連鎖して学習が進まない。正解を入れれば学習が安定し、速く収束する。
- **弱点**: 推論時には正解がないので自分の予測を入力に使う。学習時と推論時の条件が違うため、推論時に一度間違えると立て直せないことがある（**露出バイアス**、exposure bias）。対策として、学習が進むにつれて正解と自分の予測を確率的に混ぜていく方法（scheduled sampling）がある。
- **問われ方**: 「教師強制で次の時刻の入力に使うもの」→ 1つ前の時刻の**正解データ**。

## 5-7 AttentionとTransformer

### 系列モデルの系譜（なぜ次の手法が生まれたか）

| 年 | 手法 | 解決したこと | 残った問題 |
|---|---|---|---|
| 1986〜1990 | **RNN**（Jordan、Elman） | 系列を順番に処理し、過去を記憶できる | 長期依存を学べない（勾配消失） |
| 1997 | **LSTM**（2014 **GRU**） | ゲートとセルで長期の記憶を保てる | 入力と出力で長さが違う変換が苦手 |
| 2014 | **Seq2Seq** | エンコーダ・デコーダで系列 → 系列の変換 | 入力全体を**固定長ベクトル1本**に詰め込むので、長い文で精度が落ちる |
| 2014〜2015 | **Seq2Seq ＋ Attention** | 出力の各単語で、入力の**どの単語を見るか**を選べる | RNN が土台なので**並列化できず遅い**。遠い単語どうしの関係も RNN を何段も経由する |
| 2017 | **Transformer** | RNN を捨て、**Attention だけ**で構成。全単語を**同時に並列処理**でき、遠い単語どうしも1段で直接つながる | 計算量が系列の長さの**2乗**に比例して増える |
| 2018〜 | BERT、GPT、ViT、LLM | Transformer を大規模に事前学習 | → 06章 |

### アテンション（Attention、注意機構）
- **一言で**: 出力を作るときに、入力のうち**どこに注目するか**の重みを計算し、重要な部分の情報を重点的に取り出す仕組み。
- **なぜ生まれたか**: Seq2Seq は入力文全体を1本の固定長ベクトルに押し込んでいた。Attention 付きでは、デコーダが1語出すたびに、エンコーダの**すべての時刻の隠れ状態**を見直し、今必要な部分を重み付きで集めて使う。翻訳で「cats」を出すときは入力の「猫」を、「like」を出すときは「好き」を強く見る。2014年にバダナウ（Bahdanau）、チョ、ベンジオが翻訳モデルで提案した。
- **効果**: 長い文でも精度が落ちにくくなった。さらに、注目の重みを見れば「どの入力に基づいて出力したか」がわかる（解釈性）。

### クエリ・キー・バリュー（Q・K・V）
Attention の計算を「**検索**」にたとえて、3つの役割に分けたもの。

| | 役割 | 検索のたとえ | 図書館のたとえ |
|---|---|---|---|
| **クエリ（Query）** | 今、何を探しているか | 検索ワード | 知りたいこと（質問） |
| **キー（Key）** | 各情報の「見出し」。クエリと照合される | ページのタイトル | 本の背表紙・索引 |
| **バリュー（Value）** | 各情報の「中身」。実際に取り出される | ページの本文 | 本の内容 |

**計算の手順**（Transformer のスケール化内積アテンション）
1. クエリと各キーの**内積**を取り、似ている度合い（関連度のスコア）を出す。
2. スコアを √（キーの次元数）で**割る**（**スケーリング**）。次元が大きいと内積の値が大きくなりすぎ、次のソフトマックスの出力が極端（ほぼ0か1）になって勾配が消えるのを防ぐため。
3. **ソフトマックス**で、スコアを合計1の重みに変える（どこにどれだけ注目するかの割合）。
4. その重みで**バリューを加重平均**する。これが出力。

```
Attention(Q, K, V) ＝ softmax( Q・Kᵀ ÷ √dₖ ) × V
                       └ 1〜3: 注目の重み ┘   └ 4: 中身を重みで混ぜる
```

- 普通の辞書（キーが完全一致したら値を返す）と違い、**すべてのバリューを、似ている度合いに応じて少しずつ混ぜる**「やわらかい検索」になっている。
- Q・K・V はどれも、入力のベクトルに**それぞれ別の重み行列を掛けて**作る。その重み行列が学習される。

### セルフアテンションとエンコーダ・デコーダアテンション
Q と K・V を**どこから持ってくるか**で名前が変わる。

| | Q の出どころ | K・V の出どころ | 何をするか | 使われる場所 |
|---|---|---|---|---|
| **セルフアテンション**（自己注意機構） | 同じ系列 | **同じ系列** | 1つの文の中で、各単語がほかの単語とどう関係するかを計算する | Transformer のエンコーダ・デコーダの両方 |
| **エンコーダ・デコーダアテンション**（Source-Target Attention、クロスアテンション） | **デコーダ**（出力側） | **エンコーダ**（入力側） | 出力を作るとき、入力文のどこを見るかを決める | Transformer のデコーダ、Attention 付き Seq2Seq |

- **セルフアテンションの例**: 「彼はりんごを買った。**それ**は甘かった」の「それ」を処理するとき、文中の「りんご」への重みが大きくなり、「それ＝りんご」という文脈を反映した表現になる。
- **RNN との違い**: RNN では1語目と100語目の関係を学ぶのに、99回の受け渡しを経由する。セルフアテンションは**全単語のペアを1段で直接比べる**ので、遠い関係もとらえやすい。また、全単語の計算を**同時に**行える。

### マスク付きセルフアテンション（Masked Self-Attention）
- **一言で**: デコーダのセルフアテンションで、**まだ生成していない未来の単語**を見ないように、その部分の重みを0にする（隠す）仕組み。
- **なぜ**: 文章を先頭から1語ずつ生成するとき、学習時に正解の文全体を一度に入れると、未来の答えを「カンニング」できてしまう。マスクで隠せば、学習時も推論時と同じ条件（前の単語だけを見る）にしつつ、全時刻を並列に学習できる。GPT（→ 06章）はこの仕組みのデコーダだけを使う。

### マルチヘッドアテンション（Multi-Head Attention）
- **一言で**: Attention を**複数（ヘッド）並列に**行い、結果をつなげて1つにまとめる仕組み。元の Transformer はヘッド数**8**。
- **なぜ**: 1つの Attention では、注目の重みが1種類しかない。単語どうしの関係には「主語と述語」「代名詞と指す先」「修飾関係」など多くの種類がある。ヘッドごとに別の Q・K・V の重み行列を持たせると、**それぞれ違う観点の関係**を同時にとらえられる。
- 各ヘッドの次元を小さく分けるので、ヘッドを増やしても計算量は1つの大きな Attention と同程度。

### 位置エンコーディング（Positional Encoding）
- **一言で**: 各単語が文の**何番目にあるか**の情報をベクトルにして、単語の埋め込みベクトルに**足し合わせる**仕組み。
- **なぜ必要か**: セルフアテンションは全単語のペアを同時に比べるだけなので、単語の**順番を区別できない**（単語を並べ替えても、各単語への注目の仕方は同じになる）。RNN は順番に処理するので順序が自然に入っていたが、Transformer では明示的に教える必要がある。「犬が猫を追う」と「猫が犬を追う」を区別するため。
- **方法**: 元の Transformer は、位置ごとに周期の違う **sin・cos 関数**の値を並べたものを使った（学習不要で、学習時より長い文にもある程度対応できる）。BERT などは位置ごとのベクトルを**学習**する方式を使う。最近の LLM では、位置の情報を Q・K の回転として入れる方式（RoPE）も広く使われる。

### Transformer
- **一言で**: RNN も CNN も使わず、**Attention を中心に**組み立てたエンコーダ・デコーダ型のモデル。2017年に Google の**ヴァスワニ（Vaswani）ら**が論文「**Attention Is All You Need**」で提案し、機械翻訳で当時の最高精度を出した。

**構造**（元の論文ではエンコーダ・デコーダとも**6層**ずつ積む）

```
        エンコーダ（×6層）                         デコーダ（×6層）
   入力の埋め込み ＋ 位置エンコーディング        出力の埋め込み ＋ 位置エンコーディング
            │                                         │
   ┌─[マルチヘッド セルフアテンション]           ┌─[マスク付き マルチヘッド セルフアテンション]
   │   ＋スキップ結合 → レイヤー正規化          │   ＋スキップ結合 → レイヤー正規化
   │                                            │
   │ [フィードフォワード（全結合2層）]           │ [エンコーダ・デコーダ アテンション] ←── エンコーダの出力（K・V）
   │   ＋スキップ結合 → レイヤー正規化          │   ＋スキップ結合 → レイヤー正規化
   ▼                                            │
 エンコーダの出力（デコーダの各層に K・V として渡す）  │
                                                │ [フィードフォワード]
                                                │   ＋スキップ結合 → レイヤー正規化
                                                ▼
                                          全結合層 → ソフトマックス → 次の単語の確率
```

- この章の部品が全部入っている: **セルフアテンション、マルチヘッド、エンコーダ・デコーダアテンション、マスク、位置エンコーディング、スキップ結合（5-5）、レイヤー正規化（5-4）、全結合層（5-1）**。
- **フィードフォワード層**は、各単語の位置ごとに同じ全結合層（2層）を別々に当てる。Attention が「単語どうしの情報を混ぜる」のに対し、こちらは「各単語の表現を変換する」役割。

**RNN と比べた長所・短所**

| | RNN / LSTM | Transformer |
|---|---|---|
| 処理の順番 | 1語ずつ**順番に**（並列化できない） | 全単語を**同時に**（GPU で並列化しやすい） |
| 遠い単語の関係 | 何段も受け渡すので薄まる | **1段で直接**つながる |
| 順序の情報 | 処理の順番に自然に入っている | **位置エンコーディング**で与える |
| 系列の長さ n に対する計算量 | n に比例 | **n の2乗**に比例（全ペアを比べるため）。長い文書ではメモリが大きな課題 |
| 大規模化 | 難しい | データとモデルを大きくするほど性能が伸びる → 基盤モデル・LLM へ |

- **その後**: エンコーダだけを使ったのが **BERT**、デコーダだけを使ったのが **GPT**、画像をパッチに分けて入力したのが **Vision Transformer（ViT）**（すべて → 06章）。
- **問われ方**: 「Transformer が使っていないもの」→ RNN（再帰）、CNN（畳み込み）。「順序情報を与える仕組み」→ 位置エンコーディング。「RNN に比べた利点」→ 並列計算できる、長距離の依存関係をとらえやすい。「Transformer で使われる正規化」→ レイヤー正規化。

### 系列・画像モデルの比較

| | 得意なデータ | 情報の取り込み方 | キーワード |
|---|---|---|---|
| 全結合層 | 表形式の特徴量 | 全部とつながる | パラメータが多い |
| CNN | 画像（格子状） | **近く**だけを見る（局所）→ 層を重ねて広げる | 疎結合、重み共有、プーリング |
| RNN / LSTM / GRU | 系列 | **順番に**1つずつ、記憶を受け渡す | 隠れ状態、ゲート、BPTT |
| Transformer | 系列（現在は画像・音声にも） | **全部のペア**を一度に比べる | Q・K・V、並列化、位置エンコーディング |

## 5-8 オートエンコーダとVAE

### オートエンコーダ（自己符号化器）
- **一言で**: 入力を一度**小さく圧縮**し（エンコーダ）、そこから**元の入力を復元**する（デコーダ）ように学習するネットワーク。**出力の正解＝入力そのもの**なので、ラベルのないデータで学習できる（教師なし学習）。

```
入力 x（784次元）→ [エンコーダ] → 潜在表現 z（例: 32次元）→ [デコーダ] → 復元 x'（784次元）
                                    └ 情報の通り道を細くする           学習: x と x' の差（再構成誤差）を小さく
```

- **なぜ役に立つか**: 真ん中の細い層（潜在表現）を通すため、ネットワークは入力をそのまま写すことができず、**復元に必要な本質的な特徴だけ**を残すように学ぶ。
- **用途**: 
  - **次元削減**（PCA の非線形版のように使える → PCA は03章）
  - **異常検知**: 正常データだけで学習すると、異常データはうまく復元できない。**復元の誤差が大きいもの＝異常**と判定できる。工場の不良品検知などで使われる。
  - **ノイズ除去**: ノイズを加えた入力から**元のきれいな入力**を復元するよう学習させたものを**デノイジングオートエンコーダ**という。
  - **事前学習**（下）
- **問われ方**: 「オートエンコーダの入力と出力の関係」→ 出力が入力と同じになるように学習する。「オートエンコーダの異常検知の考え方」→ 復元誤差が大きいものを異常とする。

### 事前学習と積層オートエンコーダ
- **事前学習**: 本番のタスクを学習する前に、別の（多くはラベルなしの）データで重みをあらかじめ学習しておくこと。
- **なぜ生まれたか（2006年ごろ）**: 当時は、深いネットワークを初めから誤差逆伝播法で学習すると、勾配消失で入力側の層がうまく学習できなかった。そこで、**1層ずつ**オートエンコーダとして学習して良い初期値を作り、最後に全体を微調整する方法が考えられた。
- **積層オートエンコーダ**（Stacked Autoencoder）: オートエンコーダを積み重ねたもの。
  1. 1層目をオートエンコーダとして学習する（入力を復元できるように）。
  2. 1層目の出力（潜在表現）を入力にして、2層目をオートエンコーダとして学習する。これを層の数だけ繰り返す（**層ごとの貪欲な事前学習**）。
  3. 最後に出力層を付け、ラベル付きデータでネットワーク全体を**ファインチューニング**（微調整）する。
- **人物**: 2006年に**ヒントン**らが、層ごとの事前学習で深いネットワークを学習できることを示した（ディープビリーフネットワーク。制限付きボルツマンマシンを積み重ねる方式）。オートエンコーダを積み重ねる方式はベンジオらが2006〜2007年に整理した。試験では「ヒントンによる事前学習 → ディープラーニングの始まり」の文脈で問われることが多い。
- **現在**: ReLU、重みの初期値（Xavier・He）、バッチ正規化、スキップ結合が整ったため、深いネットワークは**事前学習なしで**直接学習できるようになり、積層オートエンコーダはほぼ使われない。一方「事前学習」という言葉は、**大量データで汎用モデルを作り、個別タスクにファインチューニングする**という形（BERT、GPT、基盤モデル → 06章）で、意味を広げて現在の主役になっている。

### 変分オートエンコーダ（VAE）
- **一言で**: 潜在表現を「1つの点」ではなく「**確率分布**（平均と分散）」として学ぶオートエンコーダ。分布から値を取り出してデコーダに通すと、**学習データに似た新しいデータを生成**できる。2013年に**キングマ（Kingma）とウェリング（Welling）**が提案。
- **なぜ生まれたか**: 普通のオートエンコーダの潜在空間は、学習データの点がばらばらに散らばっているだけで、点と点の間の空白からデコードしても意味のある画像にならない。つまり**生成には使えない**。VAE は潜在空間を**なめらかで連続した**形（標準正規分布に近い形）に整えるので、どこから値を取っても、もっともらしいデータが出る。
- **仕組み**:

```
入力 x → [エンコーダ] → 平均 μ と 分散 σ² → z ＝ μ ＋ σ × ε（ε は標準正規分布からの乱数）→ [デコーダ] → 復元 x'

損失 ＝ 再構成誤差（x と x' の差）＋ KLダイバージェンス（エンコーダの分布と標準正規分布のずれ）
```

- **再パラメータ化トリック**: 「分布からランダムに取り出す」操作はそのままだと微分できず、誤差逆伝播ができない。乱数 ε を外から与え、z ＝ μ ＋ σ × ε と書き直すことで、μ と σ について微分できるようにする。
- **KLダイバージェンス**（→ 04章 4-3）の項が、潜在空間を標準正規分布に近づける正則化の役割を果たす。
- **生成するとき**: エンコーダは使わず、標準正規分布から z を取り出してデコーダに通すだけ。
- **弱点**: 生成画像が**ぼやけやすい**。この点で GAN（くっきりした画像、→ 06章）と比較される。
- **問われ方**: 「VAE が通常のオートエンコーダと異なる点」→ 潜在変数を確率分布（平均と分散）で表す、生成モデルとして使える。

### VAE の派生モデル

| モデル | 一言で | 何を改良したか |
|---|---|---|
| **β-VAE** | 損失の KL の項に重み **β（1より大きい値）**を掛けたVAE（2017年、DeepMind） | 潜在変数の各次元が「顔の向き」「笑顔の度合い」「髪の長さ」のように**別々の意味を持つ**（**もつれを解く**、disentangle）ようになる。代わりに復元の精度は下がりやすい |
| **InfoVAE** | 入力と潜在変数の**相互情報量**を大きく保つように損失を変えたVAE（2017年） | VAE では、デコーダが強力だと潜在変数がほとんど使われなくなる（情報を持たなくなる）ことがある。それを防ぎ、潜在変数に情報が残るようにする |
| **VQ-VAE** | 潜在変数を連続値ではなく、**コードブック（辞書）の中の最も近いベクトル**に置き換えるVAE（2017年、DeepMind） | 潜在表現を**離散的なコード**（トークン）にする。ぼやけにくく、画像・音声を「単語の列」のように扱えるので、後の生成モデル（画像や音声のトークン化）に影響を与えた |

- **覚え方**: β-VAE は「**β で分離**」、InfoVAE は「**Info＝情報量**」、VQ-VAE は「**VQ＝ベクトル量子化＝離散化**」。
- GAN・拡散モデルなど、ほかの生成モデルは → 06章。

## 5-9 データ拡張

### データ拡張（Data Augmentation）
- **一言で**: 手持ちの学習データに、**意味（ラベル）が変わらない範囲の加工**をして、データを人工的に増やす手法。
- **なぜ**: ディープラーニングはパラメータが多く、データが少ないと過学習する。データを集めてラベルを付けるのは高コスト。加工で「見た目は違うが同じクラス」のデータを増やせば、汎化性能が上がる（正則化の一種と考えられる）。5-2 で見たように、CNN の構造だけでは得られない**回転や明るさの変化への強さ**も、データ拡張で身につける。
- **注意点**:
  - **ラベルが変わる加工はしない**。数字の「6」を180度回すと「9」になる。文字を左右反転すると別の文字になる。医療画像の左右（臓器の位置）にも意味がある。タスクに合った加工を選ぶ。
  - データ拡張は**学習データにだけ**行う。検証・テストデータを加工して水増しすると、性能を正しく評価できない。
  - 学習のたびに**ランダムに**加工を変えるのが普通（同じ画像でもエポックごとに少しずつ違う画像として見える）。

### 基本的な加工（画像）

| 手法 | 内容 | 何に強くなるか |
|---|---|---|
| **ローテーション**（回転） | 画像をランダムな角度で回す | 物体の**向き**の違い（衛星画像、手書き文字など） |
| **クロップ**（ランダムクロップ） | 画像の一部をランダムな位置・大きさで切り抜く | 物体の**位置・大きさ**の違い |
| **ランダムフリップ** | 左右（または上下）にランダムに反転する | 左右の向きの違い。最もよく使う基本手法 |
| **ブライトネス** | 画像**全体の明るさ**を変える | 照明の明るさの違い |
| **コントラスト** | **明暗の差**を強める・弱める | 照明条件・カメラの違い |
| **ノイジング** | ランダムなノイズ（ざらつき）を加える | 暗所撮影・センサーのノイズ |

- ブライトネスは「全体を明るく／暗く」、コントラストは「明るい所と暗い所の**差**」を変える。この区別が問われる。

### テキストのデータ拡張
- **パラフレージング**（言い換え）: 意味を変えずに表現を変える（類義語への置き換え、語順の入れ替え、別の言語に翻訳してから戻す「逆翻訳」など）。
- 画像と違い、単語を1つ変えるだけで意味が逆になる（「好き」→「嫌い」）ことがあるので、画像より慎重さが必要。

### 隠す・混ぜる手法（見分けが問われる）

| 手法 | 何をするか | ラベル | 提案 |
|---|---|---|---|
| **カットアウト**（Cutout） | 画像の一部を、**サイズ固定の正方形**で隠す（0など**固定の値**で埋める） | 元のまま | 2017年 |
| **ランダムイレイジング**（Random Erasing） | 画像の一部を、**大きさ・縦横比がランダムな長方形**で隠す（**ランダムな値**で埋める） | 元のまま | 2017年 |
| **Mixup** | 2枚の画像を**画像全体で半透明に重ねる**（例: 7:3 で混ぜる） | 混ぜた比率で混ぜる（例: 猫0.7、犬0.3） | 2017年 |
| **CutMix** | 1枚の画像の一部を**切り取り、別の画像の一部を貼り付ける** | **貼った面積の比率**で混ぜる（例: 猫0.75、犬0.25） | 2019年 |

- **隠す系のなぜ**: 物体の一部が隠れても認識できるように、**特定の部分だけに頼らず全体を見る**ことを学ばせる（目だけで顔と判断しない、など）。ドロップアウト（→ 04章）を入力画像に対して行うようなもの。
- **CutMix のなぜ**: Cutout は隠した部分が「何もない」ので情報の無駄になり、Mixup は2枚を半透明に重ねるので**不自然な画像**になる。CutMix は隠した部分に別の画像を貼るので、**情報の無駄がなく、画像の各部分は自然**なまま。Cutout と Mixup の良いところを組み合わせた手法。
- **見分け方**:
  - 隠すだけでラベルはそのまま → **Cutout**（正方形・固定サイズ・固定値）／**Random Erasing**（長方形・ランダムサイズ・ランダム値）
  - 2枚を使ってラベルも混ぜる → **Mixup**（全体を重ねる）／**CutMix**（切り貼り）

### RandAugment
- **一言で**: 回転・色調整・切り抜きなど多数の加工の候補から、**ランダムに N 個を選び、全部同じ強さ M で**適用する自動データ拡張。2019年に Google が提案。
- **なぜ生まれたか**: 加工の組み合わせと強さを強化学習で自動探索する **AutoAugment**（2018年）は性能が高いが、探索に膨大な計算が必要だった。RandAugment は調整するハイパーパラメータを「**いくつ選ぶか（N）**」と「**どのくらい強く（M）**」の**2つだけ**にし、探索をほぼ不要にした。
- **問われ方**: 「RandAugment で調整するパラメータ」→ 適用する操作の数と強さの2つ。

## 章末まとめ（暗記必須）

**人物・年号**
- 1986 Jordanネットワーク／1990 Elmanネットワーク
- 1997 **LSTM**（ホッフライター、シュミットフーバー）／2000ごろ 忘却ゲートを追加（ゲルスら）／1997 双方向RNN
- 2006 ヒントンらの**層ごとの事前学習**（ディープラーニングの始まり、→ 04章）
- 2013 **VAE**（キングマ、ウェリング）／2013 Network in Network（GAP）
- 2014 **GRU**（チョら）／2014 **Seq2Seq**（サツキーバーら）／2014 **Attention**（バダナウ、チョ、ベンジオ）
- 2015 **バッチ正規化**（イオッフェ、セゲディ）／2015 **ResNet**（カイミン・ヒーら、ILSVRC 2015 優勝、152層）
- 2016 レイヤー正規化、インスタンス正規化／2018 グループ正規化
- 2017 **Transformer**（ヴァスワニら、Google、「Attention Is All You Need」）／2017 β-VAE、VQ-VAE、InfoVAE、Cutout、Random Erasing、Mixup
- 2018 AutoAugment／2019 CutMix、RandAugment

**数値・計算**
- 出力サイズ ＝ **(入力 ＋ 2×パディング − フィルタ) ÷ ストライド ＋ 1**（割り切れなければ切り捨て）
- 出力のチャンネル数 ＝ **フィルタの枚数**
- 畳み込み層のパラメータ数 ＝ フィルタ縦 × 横 × 入力チャンネル数 × フィルタ枚数 ＋ フィルタ枚数
- サイズを保つパディング ＝ (フィルタサイズ − 1) ÷ 2（3×3 → 1、5×5 → 2）
- 2×2・ストライド2 のプーリングで縦横**半分**／プーリング層のパラメータは**0**
- 3×3 を2回重ねると受容野 5×5、3回で 7×7／3×3・拡張率2 の Dilated は 5×5 の範囲
- ResNet **152層**／Transformer はエンコーダ・デコーダ各**6層**、ヘッド数**8**
- LSTM のゲート**3つ**（入力・忘却・出力）／GRU のゲート**2つ**（更新・リセット）
- Attention ＝ softmax(Q・Kᵀ ÷ √dₖ) × V

**対応関係**
- 正規化の範囲: バッチ → **ミニバッチ全体**（CNN）／レイヤー → **1件の全チャンネル**（RNN・Transformer）／インスタンス → **1件の1チャンネル**（スタイル変換）／グループ → **1件のチャンネルのグループ**（小さいバッチ）
- 1×1畳み込み → チャンネル削減（Inception、ボトルネック）／Dilated → 受容野拡大（DeepLab、WaveNet）／Depthwise Separable → 計算量削減（MobileNet）
- 勾配消失への対策の「足し算の通り道」: ResNet の**スキップ結合**、LSTM の **CEC**
- Elman → 隠れ層を戻す／Jordan → 出力層を戻す
- セルフアテンション → Q・K・V が同じ系列／エンコーダ・デコーダアテンション → Q はデコーダ、K・V はエンコーダ
- 位置エンコーディング → Transformer に順序を教える／マスク → デコーダが未来を見ないようにする
- VAE → 潜在変数を確率分布で表す（再パラメータ化トリック）／β-VAE → 分離／InfoVAE → 相互情報量／VQ-VAE → 離散化
- Cutout → 固定サイズの正方形で隠す／Random Erasing → ランダムな長方形で隠す／Mixup → 全体を重ねる／CutMix → 切り貼り、面積比でラベル

**ひっかけ注意**
- 出力サイズの計算では、パディングは**2倍**する。チャンネル数は入力のチャンネル数ではなく**フィルタの枚数**。
- プーリング層には**学習するパラメータがない**。
- ResNet が解決したのは「過学習」ではなく、**深いネットワークの最適化の難しさ（劣化問題）と勾配消失**。
- GRU に**忘却ゲート・出力ゲートはない**（更新ゲート・リセットゲート）。LSTM の最初の論文（1997）にも忘却ゲートはなかった。
- 双方向RNN は**リアルタイム予測や逐次生成には使えない**。
- 教師強制で次の入力に使うのは**正解データ**（モデルの予測ではない）。
- Transformer は **RNN も CNN も使わない**。順序は**位置エンコーディング**で与える。計算量は系列長の**2乗**。
- Transformer の正規化は**レイヤー正規化**（バッチ正規化ではない）。
- バッチ正規化は推論時に**学習時の移動平均**を使う（推論時のバッチで計算し直さない）。
- データ拡張はテストデータには行わない。「6」と「9」のように**ラベルが変わる加工**は不可。

### 用語集の記述との相違点
- **積層オートエンコーダ**: 用語集では「トロント大学のヒントン教授らが提案」とされている。2006年にヒントンらが示したのは、制限付きボルツマンマシンを積み重ねたディープビリーフネットワーク（と、それで事前学習した深いオートエンコーダ）による層ごとの事前学習である。オートエンコーダを積み重ねて層ごとに事前学習する方式は、ベンジオらが2006〜2007年に整理したものとして知られる。G検定では「ヒントン＝事前学習」の文脈で問われることが多いため、本文では両方を書いた。
- **不変性の獲得**: 用語集では、畳み込みやプーリングによって「位置ずれ・スケール・回転など」に影響されにくくなるとしている。CNN の構造から得られるのは主に**小さな平行移動**に対する不変性で、回転や大きなスケール変化への強さは構造からはほとんど得られず、データ拡張で補うのが一般的である。また畳み込み自体は、入力が動くと出力も動く性質（不変ではなく「同変」）で、位置ずれを吸収するのは主にプーリングである。本文はこの理解に従った。
- **CEC**: 用語集の説明自体は誤りではないが、1997年の最初の LSTM は CEC ＋ 入力ゲート ＋ 出力ゲートで構成され、**忘却ゲートは2000年ごろに追加された**ことが書かれていない。忘却ゲートの追加後は、セルの値は「常に一定」ではなく忘却ゲートで調整される。本文に補足した。
